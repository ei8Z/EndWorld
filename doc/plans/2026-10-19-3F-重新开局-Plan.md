# 3F-1 重新开局实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development 或 superpowers:executing-plans 按任务实现。步骤用 `- [ ]` 跟踪。

**Goal:** 死亡后可二次确认重新开局，清空本局 DB/内存/账本并轮换 MemOS 身份，回到初始化页。

**Architecture:** `GameRepository.restartGame()` 负责数据与内存复位；`GameViewModel.restartGame()` 负责 UI 状态；`DeathOverlay` 负责确认交互。`MainActivity` 不改，靠 `playerState == null` 自动切页。

**Tech Stack:** Kotlin 2.0、Room 2.6、Compose、Coroutines、JUnit4/Robolectric/MockK。

**Spec:** `doc/plans/2026-10-19-3F-重新开局-Spec.md`

## Global Constraints

- 不新增 DB 迁移；不改场景触发/提示词。
- 测试数只增不减；当前基线 **394 / 0**。
- 不引入 `!!`；不为编译改断言。
- 中文提交；每任务一个提交。

## Review Focus

- **重启时仍有流在跑**：`restartGame` 必须由 VM 先取消 `streamJob/accelerationJob`，避免清库后旧协程继续写。
- **`clearAllTables()` 失败**：DB 异常时 UI 不能假装成功，必须显示错误并保留死亡态。
- **重复确认**：连点「重新开始」只执行一次，第二次不得重复清库/轮换 id。
- **`playerState` 为 null 的瞬间**：`MainActivity` 切到初始化页；VM 的死亡观察协程不得把状态又改回 `isDead=true`。
- **取消确认**：点“取消”不得调用 `onRestart`。

**Step 3: 实现**

```kotlin
private var restartJob: Job? = null

fun restartGame() {
    if (restartJob?.isActive == true) return
    streamJob?.cancel()
    accelerationJob?.cancel()
    restartJob = viewModelScope.launch {
        _isLoading.value = true
        try {
            repository.restartGame()
            _isDead.value = false
            _deathCause.value = ""
            _deathNarrative.value = ""
            _speedMode.value = SpeedMode.NORMAL
            _suggestions.value = emptyList()
            _currentStory.value = ""
            _error.value = null
        } catch (e: Exception) {
            _error.value = "重新开始失败: ${e.message}"
        } finally {
            _isLoading.value = false
        }
    }
}
```

# 3F-4 C4 继承实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development 或 superpowers:executing-plans。

**Goal:** 死亡后可一键继承：保留世界、重建默认新角色、好感 ×0.3、时间回第 1 天、展示前代纪事。

**Architecture:** `GameRepository.inheritWorldV22()` 负责 DB/内存继承并返回摘要；ViewModel 负责防重入、死亡态清理、摘要 StateFlow 与自动开局行动；Compose 死亡层加继承入口与摘要卡片。

**Spec:** `doc/plans/2026-10-19-3F-4-C4继承-Spec.md`

## Global Constraints

- 不新增 DB 表/迁移；不改「重新开始」行为。
- 世界保留：势力/区域/事件/NPC（含记忆、KEY、pair 关系）/已知地点；`stable_user_id` 不轮换。
- 好感：`abs(old) < 20 → 0`，否则 `clamp(old × 0.3, -80, 80)`；stage 重算、情感标签清空。
- 玩家/背包/时间重置为默认；背包空（与新局一致）。
- 摘要只展示，不进 prompt/MemOS。
- 当前基线 **423 / 0**；测试只增不减；无 `!!`。

## Review Focus

- **半继承**：任一步失败不能留下“世界已被折算、玩家未换”或反之；顺序与事务边界。
- **状态机**：继承后必须重建，否则仍用旧角色的 seeded 状态；但 `v3Loaded` 不能置 false（否则会重载并覆盖保留的 V3 世界）。
- **账本**：`lastMidnightSettlementDay` 与 `settlementLedger` 归 1，避免继承后立刻补结算。
- **摘要**：只取最近 10 条；空历史返回空串；不新增表。
- **重复点击**：VM 与 UI 双层防重入。
- **pair 关系**：保留，不能因 NPC 好感折算被清空。

**Step 1: 测试（真 Room + Robolectric）**

1. 好感折算：seed NPC 好感 80 / 10 / -100 → 24 / 0 / -30；emotionalTags 清空；stage 重算。
2. 世界保留：seed faction/region/event/NPC 记忆/pair 行；继承后数量与内容不变；pair 值不变。
3. 玩家重置：名称「继承者」、HP/SP 满、饥饿/口渴 50、技能/装备/伤病清空、userId 不变。
4. 时间：`第1天` / `清晨` / `360` / `避难所`；`lastMidnightSettlementDay == 1`。
5. 背包：继承前 seed 物品，继承后为空。
6. 摘要：seed 12 条 history → 只含最后 10 条；空历史 → `""`。
7. 状态机：继承后 `stateMachine.clock.currentDay == 1`；再次读取不会清世界。

**Step 2: 实现**

```kotlin
suspend fun inheritWorldV22(): String {
    val oldPlayer = playerDao.getPlayerState() ?: error("没有可继承的玩家")
    val oldWorld = worldDao.getWorldInfo() ?: error("没有可继承的世界")
    val summary = buildLegacySummary(historyDao.getAllHistory().first())

    database.withTransaction {
        playerDao.updatePlayerState(defaultSuccessor(oldPlayer))
        worldDao.updateWorldInfo(resetWorld(oldWorld))
        inventoryDao.syncInventory(emptyList())
    }

    for ((id, record) in npcRuntime) {
        val old = record.affinity.affinity
        val next = if (abs(old) < 20) 0 else (old * 0.3f).toInt().coerceIn(-80, 80)
        record.affinity.affinity = next
        record.affinity.relationshipStage = next.toRelationshipStage()
        record.affinity.emotionalTags.clear()
    }
    persistV3State()

    stateMachineInstance = null
    lastMidnightSettlementDay = 1
    settlementLedger.mark(1)
    // 清运行时缓冲：expectedChanges / localSummaryLog / lastAccelerationSummary / pendingSceneNotes / isAccelerating
    return summary
}
```

- `defaultSuccessor`：保留 `userId`、`doomType`、`doomLevel`；其余按 Spec 默认。
- `resetWorld`：保留 `macroSituation` / `knownPointsJson` / `triggeredWorldEventIdsJson`，重置日期/时间/场景/分钟。
- `buildLegacySummary`：`takeLast(10)`，格式见 Spec；`action` 空用「继续生存」，`story` 取前 60 字。
- `persistV3State()` 必须成功；失败向上抛，让 VM 显示错误。
- 删除旧 `inheritWorld`，避免两套语义。

**Interfaces:**

**Step 1: 测试**

- 成功：`repository.inheritWorldV22()` 返回摘要 → `isDead=false`、`deathCause/Narrative` 清空、`legacySummary` 设置、调用一次 `generateOpeningAction` 并 `sendAction`。
- 重复点击：`inheritJob` 活跃时只调用一次。
- 失败：异常 → 死亡态保留、`error` 含“继承失败”、摘要为空。
- `dismissLegacySummary` 清空。

**Step 2: 实现**

```kotlin
fun inheritWorld() {
    if (inheritJob?.isActive == true) return
    streamJob?.cancel(); accelerationJob?.cancel(); accelerationExitJob?.cancel()
    inheritJob = viewModelScope.launch {
        _isLoading.value = true
        try {
            val summary = repository.inheritWorldV22()
            _legacySummary.value = summary
            _isDead.value = false
            _deathCause.value = ""
            _deathNarrative.value = ""
            _suggestions.value = emptyList()
            _currentStory.value = ""
            _error.value = null
            val (action, parsed) = repository.generateOpeningAction(playerState.first()?.doomLevel ?: 1)
            sendAction(action, parsed)
        } catch (e: Exception) {
            _error.value = "继承失败: ${e.message}"
        } finally {
            _isLoading.value = false
        }
    }
}
```

- 不调用 `initializeNewGameV22` / `OpeningModule.prepare`（会清世界）。
- 首轮行动使用 `generateOpeningAction`，与初始化页 Phase 2 一致。

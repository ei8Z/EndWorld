# 2026-10-19 第 1C 批：死亡闭环 + 加速模式

对应报告 P1-6、P1-7。产品口径已确认：**最小闭环，禁用假恢复**（读档/继承在 C4 前不可用）。

## Task 1：加速模式收尾（P1-7）

`GameViewModel.setSpeedMode` 现在只有 `ACCEL → NORMAL` 会调 `exitAcceleration`；`ACCEL → DECEL` 只改 UI。

改为任何离开加速都走同一收尾：

```kotlin
fun setSpeedMode(mode: SpeedMode) {
    val previous = _speedMode.value
    if (previous == SpeedMode.ACCELERATION && mode != SpeedMode.ACCELERATION) {
        exitAcceleration(targetMode = mode)
        return
    }
    applySpeedMode(mode)
}

private fun applySpeedMode(mode: SpeedMode) {
    _speedMode.value = mode
    when (mode) {
        SpeedMode.ACCELERATION -> enterAcceleration()
        SpeedMode.NORMAL -> uiModeManager.settleMode(hasThreats = false, isSafeZone = true)
        SpeedMode.DECELERATION -> uiModeManager.settleMode(hasThreats = true, isSafeZone = false)
    }
}
```

`exitAcceleration(targetMode: SpeedMode = SpeedMode.NORMAL)` 收尾后 `applySpeedMode(targetMode)`，不再硬编码 NORMAL。

加速中禁止行动：

- `sendAction` 开头：`if (_speedMode.value == SpeedMode.ACCELERATION) { _error.value = "加速中无法行动，请先减速"; return }`。
- `startStream` 同样守卫（防 retry 绕过）。
- `GameScreen` 底部输入与发送按钮 `enabled` 增加 `speedMode != SpeedMode.ACCELERATION`。

## Task 2：死亡闭环（P1-6，最小）

### 2.1 入口与各时间路径判死

- `sendActionStream` 开头、`seedStateMachine` 之前：读 `currentPlayer` 后用 `checkPlayerDeath(hp,hunger,thirst)`；非 null 直接 `trySend(PlayerDied(cause, "你已无法行动。"))`、`close()`、`return@callbackFlow`，不调用任何 AI。
- `processBranch` 在 `processBranchAction` + SP 消耗后、构建响应前判死；死亡则 `playerDao.updatePlayerState(...)` 落 HP，`trySend(PlayerDied(...))` 后 return。
- `exitAcceleration` 收尾时落玩家状态（`playerDao.updatePlayerState(player.copy(hp=..., hunger=..., thirst=...))`）；HP≤0 由 ViewModel 观察流捕获。

### 2.2 死亡落库

主线死亡分支现在只写 player。改为在 `database.withTransaction` 内写：

- `playerDao.updatePlayerState(hp/hunger/thirst)`
- `worldDao.updateWorldInfo(world.copy(totalGameMinutes, currentDate, currentTime))`
- `settlementLedger.mark(stateMachine.clock.currentDay)`

保证死亡时刻的世界时间/账本不丢。

### 2.3 重启仍死亡

`GameViewModel` 增加 init 观察：

```kotlin
init {
    viewModelScope.launch {
        playerState.collect { p ->
            if (p == null) return@collect
            val cause = repository.checkPlayerDeath(p.hp, p.hunger, p.thirst)
            if (cause != null) {
                _isDead.value = true
                if (_deathCause.value.isBlank()) _deathCause.value = cause
            } else {
                _isDead.value = false
            }
        }
    }
}
```

### 2.4 禁用假恢复

- `inheritWorld()`：不动 DB、不清 `_isDead`；`_error.value = "继承功能尚未开放（C4）"`。
- `reloadFromSave()`：重读 player；仍死亡则保留 `_isDead=true`，`_error.value = "没有可用的死亡前存档"`。
- `DeathOverlay`：读档/观察/继承三个按钮 `enabled=false`，下方加一行「当前版本死亡后请重启游戏；读档与继承将在 C4 提供」。
- 保持 `onObserve` 参数以少改调用方，但同样禁用。

# 2026-10-19 第 1D 批：首次好感污染 + V2 五表事务

对应报告 P1-5、P1-9。两条都是 defect，不加产品功能。

## Task 1：P1-5 首次提取好感被 upsert 污染

根因：`syncGameData` 先 `npcDao.upsertNpcDepth(delta=0)` 插入 `affinity=0` 的新行；之后提取分支若现读同名 legacy 行会得到 0 → `(0-50)*2 = -100`。跨轮/跨进程都会复现。

最终实现（评审后收紧）：

1. `GameRepository` 增加 `legacyAffinitySnapshot: Map<String, Int>?`；`ensureV3WorldLoaded()` 首次加载时冻结一次，`resetV3World()`（新局）置空。
2. 冻结时**过滤 `affinity == 0` 的行**：V3 之后 `upsertNpcDepth(delta=0)` 是 `npc_relations` 唯一生产写入者，0 行代表“没有 legacy 信号”，不是真实 legacy；真实旧档 80 行不受影响。
3. `baseAttitudeFor` 只读冻结快照；`syncGameData` 与 `tryV3NpcExtraction` 两条提取路径都不再在 upsert 之后现读 DB。
4. `NpcDao.clearAll()`（`DELETE FROM npc_relations`）；`initializeNewGameV22` 写 initialPlayer 前调用，新局不继承旧档关系。

测试：

- 新档首次提取（`syncGameData` 路径）→ 10，且不 MIGRATED。
- 旧档 legacy 80 → 基准 60，+20 → 80。
- 同进程上一轮只留 0 行 → 下一轮提取得 10。
- **模拟进程重启**：库里预置 0 行 → 新 repo 冻结快照 → 提取得 10（去掉过滤后该用例实测红）。
- 情报触发 `tryV3NpcExtraction` 路径 → -5，不 -95。
- 新局清档：预置旧关系 → `initializeNewGameV22` → 表为空。

## Task 2：P1-9 V2 五表写入事务 + 缺字段兜底

### 2.1 事务

`syncGameData` 包进 `database.withTransaction`：

```kotlin
private suspend fun syncGameData(...) {
    database.withTransaction { syncGameDataInternal(...) }
}

private suspend fun syncGameDataInternal(...) { /* 原函数体 */ }
```

四个调用点不改。V3 `persistV3State` 仍走自己的事务，本批不合并。

### 2.2 缺字段兜底

`update.world.macroSituation` / `update.player.innerThought` 在 Gson 缺失时为 null 但 Kotlin 类型非空，直接 copy 会 NPE。改为：

```kotlin
private fun String?.orDefault(default: String): String =
    this?.takeIf { it.isNotBlank() } ?: default
```

写入用 `update.world.macroSituation.orDefault(oldWorld.macroSituation)`、`update.player.innerThought.orDefault(oldPlayer.innerThought)`。

测试：

- 用 Gson 反序列化一份省略 `macroSituation`/`innerThought` 的响应，跑 `processMainline`，不抛异常，world 保留旧 `macroSituation`。
- 正常响应仍写入 AI 给出的值。
- 事务：临时用 `database.withTransaction { playerDao.updatePlayerState(...); throw IOException }` 验证 Room 回滚（测试 Room 本身行为），并确认 `syncGameData` 走同一 `withTransaction`（代码审查项）。

对应报告 P1-5、P1-9。两条都是 defect，不加产品功能。

## Task 1：P1-5 首次提取好感被 upsert 污染

根因：`syncGameData` 先 `npcDao.upsertNpcDepth(delta=0)` 插入 `affinity=0` 的新行，随后提取分支 `baseAttitudeFor` 读同名 legacy 行得到 0 → `(0-50)*2 = -100`。

修法：

1. `syncGameData` 开头、任何写库之前，抓一次 legacy 快照：

```kotlin
val legacyAffinityBefore = npcDao.getAllNpcs().first()
    .associate { it.name to it.affinity }
```

2. `baseAttitudeFor` 增加可选参数，优先用快照：

```kotlin
private suspend fun baseAttitudeFor(
    name: String,
    factionId: String?,
    legacySnapshot: Map<String, Int> = emptyMap()
): Int {
    val legacy = legacySnapshot[name]?.let(::v3AffinityFromLegacy)
    return legacy ?: if (factionId != null) 0 else -10
}
```

提取分支传 `legacyAffinityBefore`。**不要**再在 upsert 之后读 DB。

3. 新局清 legacy：`NpcDao` 增加

```kotlin
@Query("DELETE FROM npc_relations")
suspend fun clearAll()
```

`initializeNewGameV22` 在写入 initialPlayer 前调用 `npcDao.clearAll()`，避免新游戏继承旧档 NPC 关系。

测试：

- 新局 + `npcUpdate{name="A", affinityDelta=10}`、无旧关系、无 faction → 提取后 `affinityFor("npc_A")` 为 10（-10 基准 +20），`departure.status != MIGRATED`。
- 旧档已有 `npc_relations(A, affinity=80)` 时首次提取 → 基准 `(80-50)*2=60`，+20 → 80；证明快照仍生效。
- 新局清档：预置旧关系 → `initializeNewGameV22` → `npc_relations` 为空。

## Task 2：P1-9 V2 五表写入事务 + 缺字段兜底

### 2.1 事务

`syncGameData` 包进 `database.withTransaction`：

```kotlin
private suspend fun syncGameData(...) {
    database.withTransaction { syncGameDataInternal(...) }
}

private suspend fun syncGameDataInternal(...) { /* 原函数体 */ }
```

四个调用点不改。V3 `persistV3State` 仍走自己的事务，本批不合并。

### 2.2 缺字段兜底

`update.world.macroSituation` / `update.player.innerThought` 在 Gson 缺失时为 null 但 Kotlin 类型非空，直接 copy 会 NPE。改为：

```kotlin
private fun String?.orDefault(default: String): String =
    this?.takeIf { it.isNotBlank() } ?: default
```

写入用 `update.world.macroSituation.orDefault(oldWorld.macroSituation)`、`update.player.innerThought.orDefault(oldPlayer.innerThought)`。

测试：

- 用 Gson 反序列化一份省略 `macroSituation`/`innerThought` 的响应，跑 `processMainline`，不抛异常，world 保留旧 `macroSituation`。
- 正常响应仍写入 AI 给出的值。
- 事务：临时用 `database.withTransaction { playerDao.updatePlayerState(...); throw IOException }` 验证 Room 回滚（测试 Room 本身行为），并确认 `syncGameData` 走同一 `withTransaction`（代码审查项）。

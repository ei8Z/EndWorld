# 3F-3 A5 NPC 间好感实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development 或 superpowers:executing-plans。步骤用 `- [ ]` 跟踪。

**Goal:** 每日 NPC 对互动产生有向好感并持久化，双方写社交快照，跨重启保留。

**Architecture:** 新表 `npc_pair_relations`（DB 11→12）；`GameRepository.pairRelations` 唯一容器；纳入 `V3WorldSnapshot` 事务；每日互动循环应用 delta 并写双方记忆。

**Tech Stack:** Kotlin、Room 2.6、KSP schema、JUnit4/Robolectric。

**Spec:** `doc/plans/2026-10-19-3F-3-NPC间好感-Spec.md`

## Global Constraints

- 只做数值/记忆/持久化；不做关系破裂、提示词、UI。
- 有向：A→B 与 B→A 独立；pairKey `min|max`。
- 无静默清档；migration SQL 与 `12.json` 的 `createSql` 逐字一致。
- 当前基线 **413 / 0**；测试只增不减；无 `!!`。

## Review Focus

- **迁移安全**：11→12 只建新表，不动旧表；`DatabasePolicyTest` 校验 SQL。
- **方向错位**：`npcAId` 是规范化后的较小 id，`affinityAtoB/BtoA` 必须按规范化方向存，不能按调用参数顺序。
- **重复行**：同一对反向输入必须命中同一 pairKey。
- **记忆双写**：双方都写；DEAD/DEMOTED 跳过；小日常社交跳过。
- **事务**：pair 表与 V3 五表同一 `save/clear` 事务，不能另开事务。

**Step 2: 实现域模型**

```kotlin
data class NpcPairRelation(
    val pairKey: String,
    val npcAId: String,
    val npcBId: String,
    val affinityAtoB: Int,
    val affinityBtoA: Int,
    val lastInteractionDay: Int,
    val lastType: String
)

fun pairKeyOf(idA: String, idB: String): String {
    val a = minOf(idA, idB)
    val b = maxOf(idA, idB)
    return "$a|$b"
}
```

`applyPairRelation(aId,bId,deltaAtoB,deltaBtoA,type,day)`：

1. 规范化 a/b；若入参顺序与规范化相反，**交换两个 delta**。
2. 取现有行或 0；累加 `coerceIn(-100,100)`。
3. 更新 day/type，写回 map，返回新行。

**Step 3: 快照**

```kotlin
    r.affinityChangeAtoB, r.affinityChangeBtoA, r.interactionType, currentGameDay)
val skipSnapshot = r.interactionType == DAILY_SOCIAL &&
    abs(r.affinityChangeAtoB) < 5 && abs(r.affinityChangeBtoA) < 5
if (!skipSnapshot) { 写 A 与 B 各一条，跳过 DEAD/DEMOTED }
```

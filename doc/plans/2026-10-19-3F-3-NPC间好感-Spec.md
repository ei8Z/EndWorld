> 日期：2026-10-19　｜　状态：**已实现（2026-10-19，`3612723` / `bbeaacc` / `6ca2b20` + 收口提交；423 tests / 0 failed，54 类，`assembleDebug` 成功）**

> 范围：只做 NPC 对好感数值、双方社交快照、持久化；不做关系破裂/提示词/UI。

## 目标

每日结算的 NPC 对互动产生有向好感变化，跨重启保留，并为双方写入社交快照，让“NPC A 对 B 的看法”有数据与记忆支撑。

## 数据模型

新表 `npc_pair_relations`：

| 列 | 类型 | 说明 |
|---|---|---|
| `pairKey` | TEXT PK | `min(npcIdA,npcIdB) + "|" + max(...)` |
| `npcAId` | TEXT | 规范化后的较小 id |
| `npcBId` | TEXT | 规范化后的较大 id |
| `affinityAtoB` | INTEGER | -100..100 |
| `affinityBtoA` | INTEGER | -100..100 |
| `lastInteractionDay` | INTEGER | 最近互动游戏日 |
| `lastType` | TEXT | 最近互动类型枚举名 |

- **有向**：A 对 B 与 B 对 A 分别累加。
- `pairKey` 规范化保证同一对只一行。

领域模型：

```kotlin
data class NpcPairRelation(
    val pairKey: String,
    val npcAId: String,
    val npcBId: String,
    val affinityAtoB: Int,
    val affinityBtoA: Int,
    val lastInteractionDay: Int,
    val lastType: String
)
```

- `V3WorldSnapshot` 增加 `pairRelations: Map<String, NpcPairRelation> = emptyMap()`。
- `V3WorldStateStore.load()` 回读；`save()` 在**同一事务**内先 `clearAll()` 再 upsert；`clear()` 一并清空。

## 每日应用

在 `executeDailySettlement` 的 NPC 互动循环中，`resolveNpcInteraction` 返回后：

```kotlin
val updated = applyPairRelation(
    aId = r.npcAId, bId = r.npcBId,
    deltaAtoB = r.affinityChangeAtoB,
    deltaBtoA = r.affinityChangeBtoA,
    type = r.interactionType.name, day = currentGameDay
)
```

规则：

- 无行则从 0 开始；有行则分别累加并 `coerceIn(-100, 100)`。
- 更新 `lastInteractionDay` / `lastType`。
- **双方**记忆队列各写一条 `NPC_SOCIAL_SNAPSHOT`（当前只写 A）。
- 快照跳过条件：`interactionType == DAILY_SOCIAL` 且 `abs(deltaAtoB) < 5 && abs(deltaBtoA) < 5`。
- 已 DEAD/DEMOTED 的 NPC 不作为快照写入对象（沿用现有 DEMOTED 过滤，补 DEAD）。

## 测试

1. **纯函数**：无行新建；A→B/B→A 独立累加；夹取 ±100；pairKey 规范化（反向输入同 key）。
2. **每日结算**：真 Room 种子两个同地点 NPC，构造可控互动（或直接调用 `applyPairRelation`），断言 pair 行与双方 memory。
3. **快照跳过**：日常社交小变化不写；争执/资源分享写。
4. **持久化**：`save` → 同库新 repo `ensureV3WorldLoaded` → pair 值一致；`clear` 清空。
5. **迁移**：`DatabasePolicyTest` 校验 12.json 建表 SQL 与 `migration11To12` 逐字一致。
6. **重新开局**：`restartGame` 后 pairRelations 为空。

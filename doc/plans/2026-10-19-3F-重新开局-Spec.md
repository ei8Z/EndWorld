# 3F-1 重新开局 Spec

> 日期：2026-10-19　｜　状态：待评审
> 上游：`doc/核心业务流程检查报告-2026-10-19.md` 的 P1-6“死亡=本局终点”接受项
> 范围：只做“死亡后重新开始”；不做读档、继承、KEY seed。

## 目标

玩家死亡后可以在应用内重新开局：确认后清空本局全部数据，回到初始化页，新角色、新世界、不检索上一局 MemOS 远程记忆。

成功标准：

- 死亡覆盖层只有「重新开始」；二次确认后才执行。
- 执行后 `playerState == null`，`MainActivity` 自动显示 `InitializationScreen`。
- 重新走到“降临末世”后，没有上一局的玩家/世界/背包/记忆/NPC/历史/账本残留。
- 新局使用新的 `stable_user_id`，MemOS 不会召回上一局记忆。

## 设计

### 1. GameRepository.restartGame()

```kotlin
suspend fun restartGame() {
    // 1. 内存 V3 与账本复位（含 MemOS 暂停、场景熔断）
    resetV3World()
    // 2. 清空所有 Room 表（V2 五表 + V3 五表 + 历史）
    database.clearAllTables()
    // 3. 丢弃状态机与 MemOS 适配器，下次访问重建
    stateMachineInstance = null
    memosAdapterInstance = null
    // 4. 清内存交互缓存
    lastPlayerNpcInteractions.clear()
    synchronized(pendingSceneNotes) { pendingSceneNotes.clear() }
    expectedChanges = null
    localSummaryLog.clear()
    lastAccelerationSummary = ""
    isAccelerating = false
    // 5. 轮换 stable_user_id；下一次 initializeNewGameV22 生成新角色 id
    context.getSharedPreferences("endworld_cache", Context.MODE_PRIVATE)
        .edit().remove("stable_user_id").commit()
}
```

`resetV3World()` 已负责：`v3Store.clear()`、factions/regions/events/npcRuntime 清空、fallback、熔断、MemOS 暂停、账本=1、快照清空、`v3Loaded=false`。

### 2. 状态机可重建

`stateMachine` 从 `by lazy` 改为可丢弃实例：

```kotlin
@Volatile private var stateMachineInstance: SurvivalStateMachine? = null

val stateMachine: SurvivalStateMachine
    get() = stateMachineInstance ?: synchronized(this) {
        stateMachineInstance ?: createStateMachine().also { stateMachineInstance = it }
    }

private fun createStateMachine(): SurvivalStateMachine { /* 原 lazy 内容 */ }
```

否则重启后 `seeded=true`、伤病/背包/目标仍留在旧实例里。

### 3. userId 与 MemOS 适配器可轮换

- `userId` 从 `by lazy` 改为 `get() = getOrCreateStableUserId()`。
- `conversationId` 同步改为 getter。
- `memosAdapter` 改为可空实例 + 同步重建；`restartGame()` 置空。
- 保留 GM 策略、API Key、其他用户设置。

### 4. ViewModel

```kotlin
fun restartGame() {
    streamJob?.cancel()
    accelerationJob?.cancel()
    viewModelScope.launch {
        _isLoading.value = true
        try {
            repository.restartGame()
            _isDead.value = false
            _deathCause.value = ""
            _deathNarrative.value = ""
            _speedMode.value = SpeedMode.NORMAL
            _suggestions.value = emptyList()
            _currentStory.value = ""
            _error.value = null
        } catch (e: Exception) {
            _error.value = "重新开始失败: ${e.message}"
        } finally {
            _isLoading.value = false
        }
    }
}
```

### 5. DeathOverlay

- 参数改为 `onRestart: () -> Unit`；删除 `onInherit/onReload/onObserve`。
- 只保留一个「重新开始」按钮。
- 点击后 `AlertDialog`：
  - 标题：重新开始？
  - 正文：将清除本局所有进度（角色、世界、NPC、记忆、历史），不可恢复。
  - 取消 / 确认。
- 确认才调用 `onRestart`；取消关闭对话框。
- 删除“需清除应用数据”等旧提示。

### 6. 不改导航

清库后 `playerState` Flow 发射 null，`MainActivity` 现有分支自动切回初始化页。

## 测试

1. **真 Room 全量清理**：播种 player/world/inventory/memory/NPC/V3 五表/history → `restartGame()` → 所有表为空、`playerState.first() == null`。
2. **账本与快照**：重启后 `lastMidnightSettlementDay == 1`，Prefs `v3_last_settled_day == 1`。
3. **状态机重建**：重启前后 `stateMachine` 不是同一实例；旧实例的伤病/背包不会带到新实例。
4. **身份轮换**：`restartGame()` 后 Prefs 中 `stable_user_id` 不存在或与之前不同；调用 `initializeNewGameV22` 后 player.userId 为新值。
5. **VM**：`restartGame()` 清空 `isDead/deathCause/deathNarrative/error`，并调用 repository（mock 验证）。
6. **UI 确认**：不做 Compose 测试；代码审查确认取消不调用 `onRestart`。

## 非目标

- 读档快照、继承（C4）。
- KEY seed、场景 3/5。
- 远程 MemOS 记忆删除（只轮换本地 user_id，旧远程数据保留但不再检索）。
- GM 策略重置（保留用户设置）。

## 验收

- 全量 394+ 全绿，`assembleDebug` 成功；新增测试 ≥5。
- 死亡后可在应用内重新开局，无需清除应用数据。
- 重启后无任何上一局 DB/内存/账本残留；新局 MemOS user_id 已轮换。
- 不新增 DB 迁移；不改场景触发/提示词。

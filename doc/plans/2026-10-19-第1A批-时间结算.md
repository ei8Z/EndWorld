# 2026-10-19 第 1A 批：主线/支线结算同轮 + 加速账本

对应报告：`doc/核心业务流程检查报告-2026-10-19.md` P1-1、P1-2。
本批**不重写** `processPreRuling` / 每小时数值管线；只把“时间推进后的结算”收敛为同步、可等待。

## Task 1：主线结算同轮 await（P1-1）

现状：`processMainline` 用 `repositoryScope.launch { v3Mutex.withLock { settleUntil(currentDay) } }` 后立刻构建 prompt，读到混合状态。

改为（`processMainline` 是 suspend，可直接等）：

```kotlin
val targetDay = sm.clock.currentDay
if (targetDay > lastMidnightSettlementDay) {
    v3Mutex.withLock { settleUntil(targetDay) }
}
```

位置在 `processPreRuling` 之后、`generatePreRulingSnapshot` 之前。失败时 `settleUntil` 内部记日志并停在原地，主线继续（不因结算失败阻断叙事）。

## Task 2：支线跨午夜也结算（P1-2）

`processBranch` 在 `sm.processBranchAction(minutes)` 之后、构建响应/落库之前：

```kotlin
if (sm.clock.currentDay > lastMidnightSettlementDay) {
    v3Mutex.withLock { settleUntil(sm.clock.currentDay) }
}
```

不改变支线的时间/消耗/伤病 tick 逻辑。

## Task 3：加速退出同步账本（P1-2 重复计数）

`exitAcceleration` 已经用 `batchCatchupResources` + `batchAdvanceNeeds` 追赶了资源与 NPC；下一次主线不应再补算同一段。退出成功（fullDays ≥ 1 路径）后：

```kotlin
lastMidnightSettlementDay = stateMachine.clock.currentDay
settlementLedger.mark(lastMidnightSettlementDay)
```

注意：
- 只在实际执行了批量追赶的分支写；`elapsed < 2h` 的早退分支不写，留给下一次主线正常结算。
- 语义取舍（写进注释）：加速期间的逐日事件/战斗不会补跑，只补资源/NPC；统一 `advanceTime` 留 1B。本批先消除“同一段加速被计两次”。

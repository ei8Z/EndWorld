# 末日求生 · AI 叙事游戏 开发文档 V2.2
## 主题：命运启示录 (Opening Reborn) —— 开局体验重构

### 1. 设计背景
在 V2.1 版本中，我们成功实现了“双 Agent 裁决与叙事”以及“生存状态机”的核心管线。然而，目前的“新游戏 (New Game)”初始化逻辑过于平淡（线性填表 + 静态背景），未能体现出 V2.1 架构中“数据权威”与“宿命无常”的核心魅力。

V2.2 旨在重构开局流程，使玩家从点击“开始游戏”的第一秒起，就感受到来自裁决 Agent 的威慑。

---

### 2. 核心变更点 (Major Changes)

#### 2.1 命运掷骰 (The Roll of Fate) —— 属性随机化
不再提供满状态开局，而是引入类似 TRPG 的初始属性抽取。
- **机制**：调用 `ClientDiceRoller` 针对 HP、SP 上限进行初始掷骰。
- **UI 表现**：在初始化界面增加“抽取生存档案”按钮，触发 `UIMode.FATE`。
- **宿命感**：玩家的性格（Personality）将提供掷骰修正（如“强壮”背景对 HP 掷骰有 +10 修正）。

#### 2.2 末日烈度协议 (Doom Level Protocol)
将 `Doom Level` 从隐藏参数变为玩家可感知的开局选择。
- **选择器**：提供 1-5 级的烈度选择。
- **影响提示**：
    - 1级（生存微光）：DC 基础倍率 0.8x，事件触发率极低。
    - 5级（灭绝倒计时）：DC 基础倍率 1.5x，夜间/恶劣天气修正叠加，致命事件频繁。

#### 2.3 章节正式切入 (Plot Introduction)
利用 `PlotManager` 强化首章仪式感。
- **流程**：初始化完成后，不直接进入对话，而是全屏展示当前章节（如：`chapter_01.json`）的**标题、背景描述及核心目标**。
- **视觉**：配合特殊的 UI 遮罩，建立章节驱动的心理预期。

#### 2.4 开局即裁决 (Opening Ruling) —— 动态遭遇启动
废弃温和的“环顾四周”开场，改为一个高风险的“初始遭遇”。
- **逻辑**：系统自动生成一个 `ActionParsed`（如：类型="移动", 子型="突围", 风险="极高"）。
- **流程**：
    1. 玩家确定角色后，直接进入“命运模式”。
    2. 裁决 Agent 判定玩家在灾难爆发初期的逃生结果。
    3. **判定失败**：玩家可能带伤（Injury）或处于低 SP 状态进入游戏。
    4. **判定成功**：获得额外的初始物资。
- **目的**：通过首轮判定确立“状态机是唯一真理”的游戏规则。

```kotlin
    // 4. 发送主线行动，触发 Reasoner + Storyteller
}
```

#### 3.2 状态机增强 (Phase 11 补完)
- 在 Room 实体中增加 `hp`, `sp`, `hunger`, `thirst`, `fatigue` 的持久化字段。
- 确保 `seedStateMachine` 能恢复这些数值，实现真正的跨重启状态保持。

### 4. 视觉与音效 (VFX & SFX)
- **FATE 模式**：初始化时的掷骰过程必须伴随心跳声（AudioHint）和屏幕暗色波纹。
- **沉浸过渡**：从初始化界面到第一章标题展示采用无缝缩放动画。

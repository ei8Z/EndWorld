  ---
要支持多角色，需要改什么

核心改动（架构级）

1. 好感度从 1:1 变为 N:N

当前：NPC.affinity 是一个标量——对"玩家"的好感度。

需要变为：NPC.affinity[characterId]——对每个角色的独立好感度。关系阶段、情感倾向标签、记忆队列中的"与玩家相关"标记，全部需要按 characterId 索引。

这会影响场景2（关系阶段跨越——对角色A跨越但对角色B没有）、场景3（战斗死亡判定——NPC 的好感度是对哪个角色的）、以及叙事Agent生成的 NPC 对话风格（对角色A 热情、对角色B 冷漠）。

2. RulingContext 增加角色维度

当前：playerAction、worldSnapshot 隐含"唯一玩家"。

需要变为：每次组装 RulingContext 时，指定 activeCharacterId。不同角色在不同位置、不同状态、看到不同的 nearbyNpcs、与不同的 controllingFaction 交互。

这意味着 processPlayerAction 需要接收 characterId 参数，advanceWorldTime 需要同时推进所有活跃角色的被动消耗。

3. "信息以玩家为中心" 变为 "信息以当前角色为中心"

当前：模拟层计算全局，但只有抵达玩家所在区域的信息被叙事层使用。

多角色下：每个角色有自己的"可见世界"。角色A 在 Region_X 不知道 Region_Y 发生的事——除非角色B 在 Region_Y 并与之通信。这其实是一个**信息迷雾（Fog of War）**机制，比单主角更有深度。

4. 叙事Agent 需要支持多视角

当前：第一人称固定视角。

多角色下：叙事Agent 需要根据 activeCharacterId 切换叙事声音。角色A 是谨慎的医生，叙事应该冷静、观察细致；角色B 是莽撞的战士，叙事应该直接、充满行动感。System Prompt 需要注入当前角色的性格/身份/语气。

这其实是一个叙事丰富度的飞跃——同一个事件，从不同角色的视角看到的是完全不同的故事。

次要改动（数据模型级）

5. 生存状态机管理 N 个角色

当前：单例模式管理一个玩家。

需要变为：Map<CharacterId, SurvivalState>。每个角色独立追踪 HP/SP/饱食度/背包/伤病。一个角色死亡不影响其他角色。死亡后世界不"暂停"——自动切换到另一个存活角色。

6. 加速模式按角色独立运作

当前：一个玩家加速 = 整个世界快进。

多角色下：角色A 在加速（前往蓝河哨站，耗时2天），角色B 在正常模式（与李队长对话，耗时30分钟）。这两个时间线需要协调——角色B 的30分钟行动发生在角色A 的2天加速的哪个时间点？这需要时间线同步机制：当角色A 加速了2天后，角色B 如果还在"2天前的时间点"，玩家切换到角色B
时需要追赶2天的时间。

7. 好感度的"全局"与"局部"

当前：好感度是全局的——李队长对玩家好感度+80，无论玩家在哪。

多角色下：一个角色可能听说另一个角色的事迹（通过 NPC 转述、环境线索）而间接产生好感度变化。这打开了"声望系统"的可能性——角色不必亲自见面就能影响 NPC 的态度。

  ---
结论

当前 V3.0 的基础架构不能直接支持群像多角色，但支撑它的底层系统几乎全部兼容。问题集中在表示层（好感度是标量、RulingContext 是单数、叙事是第一人称、生存状态机是单例）而非模拟层（世界引擎/NPC行为/事件系统完全不受影响）。
```
┌──────────────┬────────┬───────────────────────────────────────┐
│     层级     │ 兼容度 │                需要改                 │
├──────────────┼────────┼───────────────────────────────────────┤
│ 世界规则引擎 │ 100%   │ 零                                    │
├──────────────┼────────┼───────────────────────────────────────┤
│ NPC 行为系统 │ 80%    │ 好感度改为 per-characterId            │
├──────────────┼────────┼───────────────────────────────────────┤
│ 事件系统     │ 100%   │ 零                                    │
├──────────────┼────────┼───────────────────────────────────────┤
│ Agent 架构   │ 60%    │ RulingContext + 叙事视角 + 裁决上下文 │
├──────────────┼────────┼───────────────────────────────────────┤
│ 生存状态机   │ 30%    │ 从单例改为多角色管理                  │
├──────────────┼────────┼───────────────────────────────────────┤
│ 时间模型     │ 40%    │ 多角色时间线同步                      │
└──────────────┴────────┴───────────────────────────────────────┘
```
V4 的核心挑战不是模拟层的复杂度，而是时间线协调——当多个角色以不同速度在不同地点行动时，如何保持世界状态的一致性。其他改动（好感度、生存状态机、叙事视角）都是数据模型和接口层面的扩展，改动范围清晰。

这确实适合作为 V4 的升级方向——V3.0 把世界模拟的基础打牢了，V4 在它上面加"多视角"层是自然的演进路径。

### 🔴 问题1：世界规则引擎 §4.2 AI评估输入结构未同步更新多触发格式

**涉及文档**：世界规则引擎 §4.2 vs Agent §5.4

**问题描述**：

第四轮审核将 Agent §5.4 的 User Message 更新为多触发列表格式：

```
【触发事件】（可能多个同时触发，若仅1个触发事件则只列1条）：
- [阈值类型1] [势力/区域名称1] [具体指标1] 从[旧值1]变为[新值1]，跨过[阈值线1]
- [阈值类型2] ...
```

但世界规则引擎 §4.2 的"AI评估的输入结构"**仍然使用旧版单触发格式**：

```
【触发事件】：[阈值类型] [势力/区域名称] [具体指标] 从[旧值]变为[新值]，跨过[阈值线]
```

世界规则引擎 §5 Step 6 明确说"若触发数>1，合并为一次AI评估"，但 §4.2 的输入模板没有体现这个合并能力。这是第四轮修复时的遗漏——Agent §5.4 是 AI 接收的最终 User Message，但世界规则引擎 §4.2 是代码组装 AI 请求的参考模板。两者不一致时，代码实现者按世界规则引擎模板组装，导致多触发场景下 AI 仍然只收到单事件。

**后果**：代码实现者按世界规则引擎 §4.2 的模板组装 AI 请求 → 多阈值同时触发时传入数据不完整 → 与 Agent §5.4 的设计意图相悖。

**修改建议**：将世界规则引擎 §4.2 的输入结构同步为多触发格式：

```
【触发事件】（可能多个同时触发，若仅1个则只列1条）：
- [阈值类型1] [势力/区域名称1] [具体指标1] 从[旧值1]变为[新值1]，跨过[阈值线1]
- [阈值类型2] [势力/区域名称2] [具体指标2] 从[旧值2]变为[新值2]，跨过[阈值线2]

【当前世界状态】：
...

【请评估】：
1. 综合所有触发事件，该势力/区域最可能做出的反应是什么？
...
```

### 🔴 问题2：Agent §6 实现类映射未列出第四轮新增的 `buildStorytellerAccelExitUserMessage()`

**涉及文档**：Agent §3.3 vs Agent §6

**问题描述**：

Agent §3.3 在第四轮新增了加速退出模式的 User Message 方法：

> "V3.0 加速退出模式（V2.7 新增）：调用 `PromptBuilder.buildStorytellerAccelExitUserMessage()`（新建方法）"

但 Agent §6 实现类映射表中叙事Agent 行仍然只有旧方法：

```
| 叙事Agent | `StorytellerApiClient` | ... | `PromptBuilder.buildStorytellerUserMessage()` | 已实现 |
```

新增的 `buildStorytellerAccelExitUserMessage()` 没有出现在映射表中。开发者在 §6 检索实现任务时会遗漏这个方法。

**后果**：V2.7 实现时，开发者按 §6 映射表分配任务，遗漏 `buildStorytellerAccelExitUserMessage()` → 加速退出模式缺少叙事Agent 的输入组装逻辑。

**修改建议**：更新 §6 叙事Agent 行的 User Message 列：

```
| 叙事Agent | `StorytellerApiClient` | `PromptBuilder.buildStorytellerSystemPrompt()` | 正常/减速：`PromptBuilder.buildStorytellerUserMessage()`；加速退出：`PromptBuilder.buildStorytellerAccelExitUserMessage()`（V2.7新增） | 已实现 / V2.7 |
```

### 🟡 问题3：V3.0 总纲 §3.3 说"增强"模板，Agent §4.0 说"替代"模板引擎

**涉及文档**：V3.0 总纲 §3.3 vs Agent §4.0

**问题描述**：

V3.0 总纲 §3.3（及 §6.3）的未来扩展描述：

> "可用于**增强**本地模板的文本多样性和自然度"

Agent §4.0 的未来扩展描述：

> "可用于**替代**模板引擎，提升本地阶段文本的多样性和自然度。届时将本地阶段从模板引擎切换为本地模型"

"增强"（enhance）意味着模板引擎作为基础保留，本地模型在模板之上增加文本变体。"替代"（replace）意味着完全移除模板引擎，本地模型独立完成文本生成。两者对 V3.1 的升级路径有完全不同的含义：
- 增强路径：模板 + 模型混合，模板保底，模型润色
- 替代路径：模型独立运行，模板仅作降级回退

**后果**：V3.1 规划时产生两种不同的技术方案理解，可能导致架构争论。

**修改建议**：统一为一种表述。推荐 Agent §4.0 的方案（"替代"更明确），将 V3.0 总纲中的两处"增强"改为"替代"：

V3.0 总纲 §3.3 和 §6.3 中：
```
可用于替代本地模板引擎，提升本地阶段文本的多样性和自然度
```

### 🟡 问题4：场景7 触发条件的逻辑门 —— Agent "且" vs NPC "或"

**涉及文档**：Agent §5.10 vs NPC §5.2

**问题描述**：

Agent §5.10 触发条件：

> "NPC 出现在非预期位置**且**原因复杂（永久调整类型）"

NPC §5.2 触发条件：

> "重度异常（永久调整，**或**异常原因复杂）"

逻辑门差异：

| 文档 | 逻辑 | 含义 |
|------|------|------|
| Agent §5.10 | AND（且） | 必须是永久调整 **且同时** 原因复杂 |
| NPC §5.2 | OR（或） | 永久调整 **或者** 原因复杂，任一满足即可 |

按 Agent 的逻辑：一个"原因简单但永久生效"的时间表变更（如 NPC 因所属势力解散而永久迁移）不会触发 AI。但按 NPC 的逻辑：这属于"永久调整"，应该触发。

NPC 文档是场景7的权威触发源（Agent 标注"触发条件：NPC §5.2"）。Agent 应跟随 NPC 的定义。

**后果**：简单原因的永久调整被跳过 → AI 不评估 → 后续叙事缺少对这一变化的解释。

**修改建议**：将 Agent §5.10 的触发条件改为与 NPC §5.2 一致：

```
**触发条件**：NPC §5.2 —— NPC 出现在非预期位置，属于重度异常（永久调整，或异常原因复杂）
```

### 🟡 问题5：V3.0 总纲 §8.2 "世界叙事Agent"描述未反映双模架构

**涉及文档**：V3.0 总纲 §8.2

**问题描述**：

V3.0 总纲 §8.2 新增部分：

> "🆕 世界叙事Agent（加速模式时间流逝摘要）"

"时间流逝摘要"仅描述了世界叙事Agent 的**云端阶段**（加速结束时的总结）。但双模架构中，世界叙事Agent 还包含**本地阶段**（加速期间的实时状态栏模板）。当前描述遗漏了本地模板引擎的存在。

对比其他新增条目的精确度：
- "世界规则引擎（纯客户端规则引擎，每日结算）"——明确标注了实现方式和结算频率
- "NPC自主行为系统（三层NPC管理，规则驱动）"——明确标注了架构和驱动方式

**修改建议**：

```
🆕 世界叙事Agent（双模：加速期间客户端模板引擎实时状态栏 + 加速结束云端AI叙事总结）
```

### 🟡 问题6：Agent §5.8 场景5 未声明跨Region预演期间不触发

**涉及文档**：Agent §5.8 vs NPC §4.3

**问题描述**：

NPC §4.3 明确约束跨Region异步预演：

> "仅判定非致死互动——死亡、离开、关系破裂等重大结果推迟到下一次每日结算"

Agent §5.8 场景5 的触发条件包含"可能导致死亡/永久离开的互动"。按照 NPC §4.3 的约束，这类互动在预演期间**不会被判定**，因此场景5 在预演期间理论上不会触发。但 Agent §5.8 的触发条件中没有注明这一例外。

虽然逻辑上自洽（预演不产生触发条件 → 所以场景5 不触发），但文档中没有显式声明，开发者可能误以为预演期间也需要检查场景5 的触发条件。

**修改建议**：在 Agent §5.8 触发条件末尾补充一句：

```
（仅在每日结算时触发，跨Region异步预演期间不触发——预演仅判定非致死互动，见NPC §4.3）
```

### 🟢 问题7：世界规则引擎 §4.2 输入中的"输出结构化JSON"与 System Prompt 原则#2 重复

**涉及文档**：世界规则引擎 §4.2 vs Agent §5.3

**问题描述**：

世界规则引擎 §4.2 AI评估输入结构评估问题 #4：

> "4. 输出结构化JSON，不要叙事文本。"

Agent §5.3 统一 System Prompt 原则 #2：

> "2. 你的输出必须是可以被代码直接执行的结构化 JSON——不要叙事文本"

两者表述几乎相同。AI 在 System Prompt 中已经收到了此指令，User Message 中再重复是冗余的。虽然对 AI 行为无负面影响，但增加了不必要的 token 消耗。

**修改建议**：从世界规则引擎 §4.2 的输入结构中移除第 4 条（保留 System Prompt 中的原则 #2）。将【请评估】从 4 条简化为 3 条。

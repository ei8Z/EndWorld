### 🔴 问题1：§4.1 模板规则优先级1存在 Kotlin 语义错误 —— `any{}` 返回 Boolean 后 `${event.eventName}` 未绑定

**涉及文档**：Agent §4.1（内部代码逻辑）

**问题描述**：

当前代码：

```kotlin
// 优先级1：致命威胁（立即警报）
if (eventProximities.any { it.distanceInRegions <= 1 && it.propagationProb > 0.5 }) {
    return "⚠️ ${event.eventName}已逼近至邻区！"
}
```

`eventProximities.any { ... }` 返回 `Boolean`——谓词内部的 `it` 变量不会泄露到闭包外部。`${event.eventName}` 中的 `event` 在此作用域中**从未被声明**。对比其他优先级的正确写法：

```kotlin
// 优先级4（正确示例）：
val approachingEvent = eventProximities.firstOrNull { ... }
if (approachingEvent != null) {
    return "${approachingEvent.eventName}仍在${approachingEvent.distanceInRegions}个区域外"
}
```

优先级4 将 `firstOrNull` 的结果绑定到 `approachingEvent` 变量后使用——这是正确的模式。优先级1 应该使用相同模式。

此外，优先级1 的语义还需要处理多个临近事件的歧义：若同时存在两个 `distanceInRegions <= 1` 的事件，应显示哪一个？建议选取 `propagationProb` 最高者。

**后果**：编译错误——Kotlin 编译器无法解析 `event` 引用。

**修改建议**：

```kotlin
// 优先级1：致命威胁（立即警报）
val immediateThreat = eventProximities
    .filter { it.distanceInRegions <= 1 && it.propagationProb > 0.5 }
    .maxByOrNull { it.propagationProb }
if (immediateThreat != null) {
    return "⚠️ ${immediateThreat.eventName}已逼近至邻区！"
}
```

### 🔴 问题2：§4.3 调用节奏图遗漏 NPC 批量追赶步骤，与 §7 调用链不一致

**涉及文档**：Agent §4.3 vs Agent §7

**矛盾描述**：

Agent §4.3 调用节奏：

```
玩家发出"恢复正常速度"：
  ├─ 停止本地循环
  ├─ 世界规则引擎执行批量追赶结算
  ├─ 调用云端世界叙事Agent（DeepSeek Pro，单次，5-15s）
  ├─ UI 展示"正在生成加速总结..."加载动画
  └─ 收到最终摘要 → 转交给叙事Agent 生成初始场景叙事
```

Agent §7 调用链（第二次审核已修复）：

```
玩家选择"恢复正常" → 世界规则引擎批量追赶结算
                   → NPC行为系统批量追赶（NPC需求+互动+离开判定）
                   → 收集自动导航报告
                   → 世界叙事Agent云端调用 → 叙事Agent → UI
```

两份描述相差两个步骤：**NPC行为系统批量追赶**和**收集自动导航报告**。这两步对世界叙事Agent 的输入至关重要——没有 NPC 批量追赶，`actualChanges` 中缺少数十种 NPC 状态变更；没有自动导航报告，`playerStatus` 无法填充。

**后果**：开发者只看 §4.3 实现加速退出流程时，会跳过 NPC 批量追赶和自动导航报告收集，导致世界叙事Agent 收到不完整的输入数据。

**修改建议**：将 §4.3 的调用节奏更新为与 §7 一致：

```
玩家发出"恢复正常速度"：
  ├─ 停止本地循环
  ├─ 世界规则引擎执行批量追赶结算（N个游戏日的资源更新+冲突判定+事件传播）
  ├─ NPC行为系统批量追赶（NPC需求+互动+离开判定）
  ├─ 收集自动导航报告
  ├─ 调用云端世界叙事Agent（DeepSeek Pro，单次，5-15s）
  ├─ UI 展示"正在生成加速总结..."加载动画
```

### 🟡 问题3：§5.3 System Prompt 原则#4 与场景1自身新增字段矛盾

**涉及文档**：Agent §5.3 原则 vs Agent §5.4 输出结构

**矛盾描述**：

Agent §5.3 统一 System Prompt 原则#4：

> "每个输出字段都有明确的 schema——严格遵守，不要添加额外字段"

Agent §5.4 场景1 输出结构在 `evaluation` 对象中新增了两个字段：

```json
{
  "evaluation": {
    ...世界规则引擎 §4.2 定义的字段...,
    "rationale": "一句话说明决策依据（≤50字）",           // ← 额外字段
    "suggestedNarrativeAngle": "一句话叙事建议（≤50字）"   // ← 额外字段
  }
}
```

世界规则引擎 §4.2 的输出结构不含这两个字段。System Prompt 指令 AI "不要添加额外字段"，但场景1 的 user message 模板要求 AI 输出包含这些"额外字段"——AI 收到两条矛盾的指令。

实际上，场景2-7也在 `decision` 外层添加了 `rationale` 和 `suggestedNarrativeAngle`（这两个字段在各场景的 output JSON 中位于 `decision` 外部、顶层），与 §5.3 的结构声明一致。但场景1 的情况特殊——两个新增字段被放在了 `evaluation` 内部而非顶层，且 System Prompt 中的"不要添加额外字段"对场景1构成了直接矛盾。

**后果**：AI 收到矛盾指令后行为不确定——可能忽略 `rationale` 和 `suggestedNarrativeAngle`，也可能因原则约束而跳过这两个字段。

**修改建议**：二选一：

方案A（推荐）：在 §5.3 原则#4 中增加例外说明：

```
4. 每个输出字段都有明确的 schema——严格遵守。场景1允许在 evaluation 对象中新增
   rationale 和 suggestedNarrativeAngle 字段（用于日志追溯和叙事Agent输入），
   但不得新增其他字段。
```

方案B：将 `rationale` 和 `suggestedNarrativeAngle` 从场景1的 `evaluation` 内部移到外部顶层，与其他场景一致。同时修改世界规则引擎 §4.2 的解析器以支持顶层额外字段。

### 🟡 问题4：§5.4 代码验证规则中 `attribute` 合法值集合遗漏资源池属性

**涉及文档**：Agent §5.4 vs 世界规则引擎 §2.2

**问题描述**：

Agent §5.4 验证规则：

> `stateChanges[].attribute` 必须为已知属性名（势力目标/士气/状态标签/控制区域），不匹配→丢弃

世界规则引擎 §2.2 定义的势力属性还包括：食物储备、水资源、医疗物资、弹药储备、领袖性格、兵力、人口、武装程度。

轻量AI 评估的 `mostLikelyReaction` 可能涉及"向周边势力求援"或"转变为掠夺模式"——这本质上涉及资源转移。若 AI 判定势力A 向势力B 求援并得到食物，合理的 `stateChanges` 应为：

```json
{"target": "势力B", "attribute": "食物储备", "change": -300},
{"target": "势力A", "attribute": "食物储备", "change": +300}
```

但在当前验证规则下，`"食物储备"` 不是已知属性名 → 被丢弃 → AI 的输出静默失败。

设计考量：是否需要限制 AI 直接修改资源池数值？当前世界规则引擎 §3.1 的池-流模型用确定性规则管理资源变化——如果 AI 也修改资源池，可能出现双重扣减或数值不一致。但另一方面，如果 AI 的评估结果不能修改资源池，那"势力间资源转移"这类质变反应就无法通过 AI 输出来实现。

**修改建议**：不直接放开资源池属性的修改权限。而应在验证规则中增加：

```
- 若 AI 输出涉及资源变更的 stateChanges（attribute 为食物储备/水资源/医疗物资/弹药储备），
  校验日志输出警告但不丢弃——代码侧按 |change| ≤ 对应资源池当前值的 50% 执行 clamp，
  并标记为 source: "ai_triggered_resource_change"（与确定性池-流更新区分）
```

### 🟡 问题5：§5.6 场景3 User Message 遗漏 CasualtyReport 中的 `severity` 字段

**涉及文档**：Agent §5.6 vs 世界规则引擎 §3.3

**矛盾描述**：

世界规则引擎 §3.3 定义的 `CasualtyReport.newInjuries` 结构：

```
newInjuries: [{npcId, severity}, ...]
```

Agent §5.6 场景3 User Message：

```
- NPC是否在 CasualtyReport 的 newInjuries 中：[是/否]
```

仅传递了"是否在名单中"（boolean），未传递 `severity` 字段。

`severity` 对 AI 判定有直接影响：轻度伤（轻伤）→ AI 可能倾向于 `spare`；重伤（失血、骨折）→ AI 可能倾向于 `kill` 或 `severe_injury`。缺少 severity 信息时，AI 无法区分"被流弹擦伤"和"被爆炸冲击波撕裂内脏"——这两种情况的生还概率天差地别。

世界规则引擎 §3.3 的 `CasualtyReport` 明确包含 severity，NPC 行为系统也据此更新伤病标记（见 NPC §4.4），但 Agent 的 User Message 模板遗漏了这一关键字段。

**修改建议**：将场景3 User Message 中的对应行改为：

```
- NPC在 CasualtyReport 的 newInjuries 中：
  · 是 → 伤情严重度：[severity 值]
  · 否
```

### 🟡 问题6：世界规则引擎 §4.2 输出结构未同步声明 `ignoreUnknownKeys` 配置

**涉及文档**：Agent §5.4 vs 世界规则引擎 §4.2

**问题描述**：

Agent §5.4 在第二次审核后新增了兼容性声明：

> JSON 解析器需配置为忽略未知字段（如 Gson 默认行为，或 kotlinx.serialization 的 `ignoreUnknownKeys = true`），以兼容 Agent 配置规范可能在 `evaluation` 对象中新增的辅助字段

但世界规则引擎 §4.2 **没有**对应的修改——其输出结构仍然不含 `rationale` 和 `suggestedNarrativeAngle`，也没有声明解析器需要容忍未知字段。两个文档在此处的"配置契约"是单向的：Agent 说"你（世界规则引擎）需要这样配置"，但世界规则引擎自己没说过。

**后果**：世界规则引擎开发者只看自己模块的文档时，可能没有意识到需要配置 `ignoreUnknownKeys`，导致严格 schema 校验时解析失败。

**修改建议**：在世界规则引擎 §4.2 的 AI 输出结构下方增加一行声明：

```
> 解析器需配置 `ignoreUnknownKeys = true`（kotlinx.serialization）或等效行为，
> 以容忍 Agent 配置规范未来可能新增的辅助字段（如 rationale、suggestedNarrativeAngle）。
```

### 🟢 问题7：§5.5 场景2 `behaviorModeChange` 是模式字符串而非枚举，§5.11 通用枚举校验规则无法覆盖

**涉及文档**：Agent §5.5 vs Agent §5.11

**问题描述**：

Agent §5.11 通用验证规则：

> 枚举字段必须在定义的合法值集合内，否则 → 取合法值集合的第一个值作为默认值

Agent §5.5 场景2 输出中的 `behaviorModeChange`：

```json
"behaviorModeChange": "警惕→开放" | "信任→疏远" | ...
```

`"警惕→开放"` 不是枚举值——它是一种**模式字符串**（旧状态 + 箭头 + 新状态），其合法值空间是所有合法关系阶段的笛卡尔积（6×6=36种组合），不可能一一枚举。§5.11 的枚举校验规则对此字段完全不适用。

虽然 §5.11 说"场景1的特定验证见 §5.4 末尾"，但场景2-7没有对应的特定验证补充。

**修改建议**：在 §5.5 末尾增加场景2的特定验证规则：

```
代码验证规则（场景2特定）：
- behaviorModeChange 必须是 "X→Y" 格式，X和Y均为合法关系阶段名
  （仇恨/敌意/中立或陌生/熟悉/信任/亲密），不匹配→丢弃，使用空字符串
- newEmotionalTags 每个标签 ≤ 10 字符，最多3个，超出截断
```

### 🟢 问题8：§4.1 `ExpectedChanges.playerVitals` 在整个加速期间只有一个初始快照，且模板规则从未使用

**涉及文档**：Agent §4.1（内部数据设计）

**问题描述**：

`ExpectedChanges` 数据类定义包含：

```kotlin
val playerVitals: PlayerVitals   // 玩家生命体征
```

两个问题：

1. **模板规则完全不引用它**：五个优先级的模板规则只使用了 `eventProximities` 和 `resourceTrends`，从未引用 `playerVitals`。这是死字段。

2. **加速期间只有一个初始快照**：`ExpectedChanges` 在加速开始时计算一次。玩家进入加速后，自动导航会消耗食物/水，可能遭遇威胁受伤——`playerVitals` 的快照在第一次模板刷新后就已过时。虽然模板规则不引用它，但如果未来版本（V3.1+）的模板想显示"当前HP: 85/100"，这个值将是错误的。

**修改建议**：二选一：

方案A：从 `ExpectedChanges` 中移除 `playerVitals`。当前模板规则不需要它，V3.1 需要时再加回来。

方案B：保留但增加注释说明 `playerVitals` 仅为加速开始时的快照，仅供云端阶段的自动导航报告引用（该报告由 `GameRepository` 独立收集，不依赖 `ExpectedChanges`）。

### 🟢 问题9：`triggerType` 完整合法值集合未在任何文档中定义

**涉及文档**：Agent §5.4 / 世界规则引擎 §4.1-4.2

**问题描述**：

Agent §5.4 场景1 输出示例中：

```json
"triggerType": "势力食物危机"
```

世界规则引擎 §4.1 定义了触发条件：

| 指标 | 警告阈值 | 危机阈值 |
|------|----------|----------|
| 食物储备 | <7天 | <3天 |
| 兵力 | <总人口×10% | <总人口×5% |
| 士气 | <30 | <15 |
| 控制区域数 | 减少50% | 减少80% |
| 威胁等级 | >60 | >85 |
| 资源丰度 | <20 | <5 |

加上 §3.2 的势力解散触发，理论上可推导出 ~12 种 triggerType（6个指标 × 2级阈值）。但没有任何文档定义完整的合法值枚举。AI 在评估时可能生成任意字符串（如 `"势力濒临崩溃"`、`"区域极度危险"`），导致下游代码无法将 `triggerType` 映射到具体行为。

**修改建议**：在 Agent §5.4 或世界规则引擎 §4.1 中增加 triggerType 的合法值枚举：

```
势力食物危机、势力食物警告、势力兵力危机、势力兵力警告、势力士气危机、
势力士气警告、势力控制区危机、势力控制区警告、区域威胁危机、区域威胁警告、
区域资源危机、区域资源警告、势力解散
```

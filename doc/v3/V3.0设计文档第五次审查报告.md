### 🔴 问题1：NPC §4.3 格式化回归——社交快照文本与AI触发条件散落

**涉及文档**：《NPC》§4.3

**问题描述**：

第四轮修订在 §4.3 "互动粒度"中新增了"NPC间互动的社交快照"段落。但该段落的插入位置**打断了原有的"罕见情况触发轻量AI评估"列表**，导致两者的层次结构混乱。

当前文本（NPC文档第387-401行）的实际排列：

```
**互动粒度**：
常规互动只记录结果（数值变更），不模拟过程。以下罕见情况触发轻量AI评估：

**NPC间互动的社交快照**：                          ← 新插入
即使是常规互动（不触发AI），也应在双方记忆队列中...  ← 新插入
社交快照确保NPC的情感变化有叙事支撑...              ← 新插入
- 涉及关键NPC                                      ← 原"罕见情况"列表项（脱离标题）
- 互动可能导致NPC死亡或永久离开                      ← 原列表项
- 互动涉及道德困境（背叛、牺牲、重大承诺）            ← 原列表项
- 互动可能显著改变势力内部结构                        ← 原列表项
```

社交快照的说明文字之后，紧跟着4个孤立的 bullet point——它们原本属于"以下罕见情况触发轻量AI评估"的列表，但现在悬挂在社交快照说明之后，好像成了社交快照的一部分。读者会困惑为什么"涉及关键NPC"会在社交快照的段落下。

**修改建议**：将"罕见情况触发轻量AI评估"的bullet point列表移至"社交快照"段落**之前**：

```
**互动粒度**：
常规互动只记录结果（数值变更），不模拟过程。以下罕见情况触发轻量AI评估：
- 涉及关键NPC
- 互动可能导致NPC死亡或永久离开
- 互动涉及道德困境（背叛、牺牲、重大承诺）
- 互动可能显著改变势力内部结构

**NPC间互动的社交快照**：
即使是常规互动（不触发AI），也应在双方记忆队列中插入一条简化的社交快照...
```

### 🟡 问题2：背景NPC首次互动时好感度变化值的计算基准不明确

**涉及文档**：《NPC》§2.2

**问题描述**：

§2.2 提取规则中的初始好感度公式：

> "初始好感度 = 群体态度基准值 + 本次互动变化值"

"本次互动变化值"是提取触发器——即"好感度变化绝对值 ≥ 10"中的变化值。但背景NPC没有个体好感度，这个变化值是相对于什么基准计算的？

推演：玩家与背景群体（群体态度=中立）互动。互动中玩家的行为对群体态度产生了+15的影响（如帮助了营地）。提取触发：|+15| ≥ 10 → 触发提取。

问题：这+15是相对于什么算的？如果相对于群体态度基准值（0），初始好感度 = 0 + 15 = 15。但如果裁决Agent在判定时计算的是"相对于如果这是一个普通NPC的预期好感度"，基准就不同了。

当前文档没有定义背景NPC互动时的"好感度变化"如何量化——背景NPC只有群体态度标签（欢迎/中立/警惕/敌意），没有数值。

**修改建议**：在 §2.2 中明确：

```
背景NPC互动时的好感度变化计算：
- 以群体态度基准值（欢迎=30/中立=0/警惕=-20/敌意=-50）为虚拟基准线
- 裁决Agent判定互动结果时，输出一个相对于该基准线的变化值
- 若该变化值的绝对值 ≥ 10，触发提取
- 提取后的初始好感度 = 基准值 + 变化值
```

### 🟡 问题3：世界规则引擎 §3.1 人力修正与 §3.3 兵力之间的关联缺失

**涉及文档**：《世界规则引擎》§3.1 vs §3.3

**问题描述**：

§3.1 资源更新公式中的"人力修正"：

> "人口中可用于采集的比例（伤病、战斗占用）"

§3.3 战斗结算中定义了兵力：

> "兵力 = 人口 × 武装率"

**逻辑缺口**：当势力处于战争状态时，武装人员（=人口×武装率）被占用去战斗，不能同时参与资源采集。但 §3.1 的"人力修正"没有引用 §3.3 的兵力参数。

当前两个公式独立运行：
- 食物生产只受"人力修正"影响（一个手动调整的参数）
- 战斗只消耗兵力和弹药

如果人力修正 = 0.8（20%的人因伤病/战斗无法采集），而武装率 = 0.5（50%的人口是士兵），两者之间没有自动关联。这意味着开发者需要手动调整人力修正来反映战斗占用，容易出现不一致。

**修改建议**：在 §3.1 "关键修正系数"表中增加人力修正的自动推导：

```
人力修正 = max(0.1, 1.0 - 武装率 - 伤病率)
其中：
- 武装率 = 兵力/人口（战斗人员被占用，不影响采集）
- 伤病率 = 受伤人口/总人口（伤病导致无法劳动）
- 下限 0.1 确保总有至少10%的人在采集（老人、轻伤者等）
```

### 🟡 问题4：V3.0 §3.3 加速模式步骤3描述滞后于势力资源优先规则

**涉及文档**：《V3.0》§3.3

**问题描述**：

§3.3 加速模式步骤3：

> "玩家角色进入**自动导航模式**：按预设生存本能行动（饿了吃背包食物、渴了喝水、遇危险逃跑），不进行策略性选择"

第三轮修订在下方增加了势力资源优先规则：

> "自动导航优先消耗势力资源池（同步扣除模拟层对应的人口天数）"

但步骤3的概要描述仍然只写"饿了吃背包食物"，没有提及"优先消耗势力资源"。

这不是逻辑矛盾——步骤3是概览，详细规则在后面——但作为阅读入口，它给人"加速期间只吃背包"的第一印象，与后面详述的势力资源优先策略冲突。

**修改建议**：将步骤3改为：

```
3. 玩家角色进入**自动导航模式**：按预设生存本能行动（优先消耗当前所在地的友好势力资源，其次为背包物资），不进行策略性选择
```

### 🟡 问题5：NPC受伤后获取医疗的机制未定义

**涉及文档**：《NPC》§3.3 vs §4.4

**问题描述**：

NPC §3.3 需求系统明确定义了"生存-医疗"需求的日增量（受伤时+360/日），以及需求满足条件（"接受治疗后归零"）。

NPC §4.4 死亡条件之一："NPC受伤且未获得医疗"。

**逻辑缺口**：触发条件（受伤）和后果（未治疗→死亡）都定义了，但**中间环节缺失**——NPC如何"获得医疗"？

- NPC可以在势力医疗物资池中自动治疗吗？（势力资源池有"医疗物资"字段）
- NPC需要玩家主动提供治疗吗？（这样所有受伤NPC的命运都取决于玩家）
- 不同战斗角色的NPC获取医疗的能力是否不同？（领袖>战斗人员>非战斗人员）

这个问题在势力资源充足但不为NPC提供医疗时格外突出：势力有医疗物资1000（单位：可治疗人次），但接触NPC老王受伤后因为没有"获取医疗"的机制，只能等待死亡。

**修改建议**：在 NPC §3.3 的需求满足行中增加：

```
- 医疗需求：接受治疗后归零。治疗来源优先级：
  1. 玩家主动治疗（玩家使用医疗物资治疗该NPC）
  2. 所在势力自动分配（仅在该势力医疗物资 > 0且NPC为战斗人员或领袖时触发，每次治疗消耗势力医疗物资）
  3. 若无以上来源，NPC保持受伤状态，医疗需求持续增长
```

### 🟢 问题6：世界规则引擎武装率与NPC战斗角色数量之间缺少一致性约束

**涉及文档**：《世界规则引擎》§2.2 vs §3.3 vs 《NPC》§3.1

**问题描述**：

世界规则引擎 §2.2 定义势力"武装程度 = 兵力/人口"（宏观比例）。

NPC §3.1 定义战斗角色为逐NPC设置的枚举值——每个接触NPC独立设定为"战斗人员"或"非战斗人员"。

世界规则引擎 §3.3 战损映射规则使用战斗角色来修正死亡概率。

**微妙的不一致**：如果势力A的武装率=0.6（理论上60%的人口是战斗人员），但该势力的10个接触NPC中只有1个被随机分配为"战斗人员"，那么宏观比例（60%）和微观比例（10%）严重偏离——战损映射的修正概率将失真。

这不是一个会导致崩溃的bug，但会削弱模拟的真实性。文档应至少注明这是一致性风险。

**修改建议**：在 NPC §3.1 战斗角色说明后增加：

```
势力内接触NPC的战斗角色分布应大致符合该势力的武装率：
- 至少 floor(势力武装率 × 该势力接触NPC数) 个接触NPC应为战斗人员
- 新提取NPC的战斗角色优先填补缺口（若势力战斗人员比例低于武装率，新NPC优先设为战斗人员）
- 此约束为弱校验——允许暂时偏离但每日结算时输出警告日志
```

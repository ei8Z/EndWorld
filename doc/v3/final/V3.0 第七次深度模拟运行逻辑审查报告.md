## 一、场景DD：AI输出JSON类型错误 — 校验规则的最后一层

### 预设状态

```
轻量AI场景1正常返回，但DeepSeek API在极少数情况下返回了错误类型的JSON：
{
  "evaluation": {
    "triggerType": "势力食物危机",
    "subjectName": 12345,                    // ← 应为字符串，返回了数字
    "mostLikelyReaction": null,              // ← 应为字符串，返回了null
    "alternativeReactions": "向周边求援",     // ← 应为数组，返回了字符串
    "stateChanges": [
      {"target": "红松", "attribute": "士气", "change": "下降十点"}  // ← 应为数值，返回了字符串
    ]
  }
}
```

### 步骤追踪

```
Step 1: 代码验证规则(§5.11)检查
  - decision/evaluation存在? ✓
  - 枚举字段合法? triggerType="势力食物危机" ✓
  - 数值字段NaN/Infinity/负数? change="下降十点" —— 不是数值类型!
  - 字符串字段为空? subjectName=12345 —— 不是字符串类型!

Step 2: 当前验证规则的覆盖盲区
  
  §5.11当前规则：
  - "枚举字段必须在定义的合法值集合内" → 仅检查枚举
  - "数值字段若为 NaN/Infinity/负数 → clamp" → 仅检查数值范围
  - "字符串字段若为空字符串 → 取默认值" → 仅检查空字符串
  
  未覆盖: JSON字段的**基础类型**错误
  - 数字代替字符串 → subjectName=12345 通过所有检查(非空✓, 非NaN✓)
  - null代替字符串 → mostLikelyReaction=null → 
    null在JSON中不是""(空字符串)，空字符串检查不触发
  - 字符串代替数组 → alternativeReactions="向周边求援" → 
    代码期望List类型 → JSON反序列化时可能崩溃(NPE/ClassCastException)
  - 字符串代替数字 → change="下降十点" → 
    Kotlin类型系统 → 反序列化时可能使用默认值(0)或抛异常

  ⚠️ 逻辑缺口 #1: 缺少JSON基本类型校验
    
  当前验证规则假设AI返回的JSON字段类型是正确的，
  只检查值的范围和合法性。但DeepSeek API可能在极少情况下
  返回错误类型的JSON(这是LLM的已知行为——偶尔混淆字段类型)。
  
  需要在JSON反序列化层增加类型安全校验:
  - 期望String的字段收到非String → 取该字段的降级默认值
  - 期望Number的字段收到非Number → 取0(或对应默认值)
  - 期望Array的字段收到非Array → 取空数组
  - 期望Boolean的字段收到非Boolean → 取false
  - null→String → 取降级默认值(与空字符串相同处理)
```

### 本场景结论：发现 1 个运行时逻辑缺口

## 二、场景EE：单极世界终局 — 一个势力控制全部区域

### 预设状态

```
经过50+游戏日的演变:
  灰烬匪帮控制了所有8个区域(逐一吞并了红松、蓝河、及其他势力)
  匪帮: 人口500, 兵力300(60%), 食物储备2000人口天, 士气90
  所有其他势力: 已解散
  所有接触NPC: 要么死亡、要么加入匪帮、要么流浪
  活跃全局事件: 仅2个(无冲突触发——没有敌对势力)
  玩家: 游荡在匪帮控制的世界中，好感度对匪帮-30(敌意)
```

### 步骤追踪

```
Step 1: 每日结算
  世界规则引擎Step 3冲突判定:
    遍历所有相邻且敌对的势力对 → 无敌对势力对 → 无冲突
  
  Step 5事件传播:
    仅2个活跃事件(难民潮+疫病)，缓慢传播中
    
  Step 6阈值触发:
    匪帮所有阈值正常(食物充足、兵力充足、士气高、控制区稳定)
    → 无阈值触发 → 零AI调用
    
  ⚠️ 逻辑缺口 #2: 单极世界下AI调用频率降至接近零——
  但叙事丰富度不应同步下降
  
  场景1(势力质变): 无阈值触发 → 零调用
  场景2(关系跨越): 仍需触发(如果玩家与匪帮NPC互动)
  场景3(战斗死亡): 无战斗 → 零调用
  场景4(生存突变): 仍需触发
  场景5(罕见互动): 仍需触发
  场景6(失踪判定): 仍需触发
  
  NPC系统的轻量AI(场景2,4,5,6,7)仍在运作——因为它们
  不是由世界规则引擎的阈值驱动的，而是由NPC自身状态变化驱动。
  ✓ 设计合理: NPC系统独立于势力间冲突
  
  但场景1的完全沉默意味着: 世界层面的"故事"不再演变。
  没有新势力出现、没有权力更迭、没有资源危机——
  除非玩家行动或EventDeck制造变化。
  
  这是单极世界的固有特征(和平=无聊)，但文档未声明这一点。
  对于玩家体验: 在单极世界中长期停留可能导致"叙事荒漠化"——
  每次行动的叙事反馈变得越来越重复。

Step 2: 玩家行动 "尝试煽动匪帮内部的叛乱"
  裁决Agent判定: 交涉DC极高(匪帮士气90, 内部稳定)
  
  如果成功: 可能触发匪帮内部分裂 → 新势力出现 → 重新激活世界冲突
  如果失败: 匪帮对玩家好感度进一步降低 → 可能触发敌对
  
  单极世界并非"死局"——玩家的行动可以打破它。
  但打破单极需要玩家有意识地采取高风险行动，
  而"加速→等待→观察"的被动策略不会改变任何事。
  ✓ 这符合设计哲学"选择有分量"。

Step 3: 信息以玩家为中心在单极世界的体现
  V3.0总纲§10: "模拟层计算全局，但只有抵达玩家所在区域的信息会被叙事层使用"
  
  如果匪帮控制了全部8个区域，玩家在Region_A:
    叙事Agent收到的zoneState: 控制势力=匪帮，威胁等级=低
    nearbyNpcs: 匪帮成员(对玩家态度=警惕/敌意)
    
  但玩家不知道Region_H发生了什么(曾经的红松营地遗址)。
  那个区域可能荒废(无势力、无NPC)或有游荡的丧尸。
  
  "信息以玩家为中心"原则在单极世界中自然运作 ✓
```

### 本场景结论：发现 1 个运行时逻辑缺口

## 三、场景FF：V2存档迁移到V3.0 — 数据模型不兼容

### 预设状态

```
V2.x存档:
  - 玩家状态: V2格式(HP, SP, 饱食度, 物资背包(V2.3精确计量))
  - NPC: V2 NpcRelation(affinity 0~100百分比语义)
  - 世界状态: 无(世界在玩家不行动时静止)
  - 剧情进度: PlotContext(章节/节点)
  - EventDeck: 26张事件卡冷却状态
```

### 步骤追踪

```
Step 1: V3.0启动，检测到V2存档
  需要迁移的数据:
  
  ✅ 可直接迁移:
    - 玩家生存状态(HP/SP/饱食度/口渴度/物资背包) —— V2.3格式直接兼容
    - 剧情进度 —— PlotContext结构不变
    - EventDeck冷却状态 —— 不变
    - MemOS长期记忆 —— 不变
  
  ⚠️ 需要转换:
    - NPC好感度: V2 affinity(0~100) → V3 affinity(-100~+100)
      NPC文档§3.5已定义转换公式: newAffinity = (oldAffinity - 50) * 2 ✓
    
    - NPC关系: V2无关系阶段概念 → V3需根据好感度推断初始关系阶段 ✓
  
  ❌ 无法从V2存档迁移(需从头初始化):
    - 世界规则引擎状态(势力/区域/资源/事件) —— V2无此数据
    - NPC三层结构 —— V2只有简单NPC列表
    - NPC需求系统 —— V2无需求数据
    - NPC时间表 —— V2无时间表
    - NPC记忆队列 —— V2仅有MemOS交互文本，无结构化记忆摘要

Step 2: 迁移后的"冷启动"问题
  
  世界规则引擎需要从头初始化:
  - 区域定义: 从配置文件加载 ✓
  - 势力初始状态: 从配置文件加载 ✓
  - 全局事件: 初始为空(无活跃事件) ✓
  - 资源池: 初始值从配置加载 ✓
  
  NPC系统:
  - V2的NPC列表 → V3的接触NPC(保留好感度和身份)
  - 但需求、时间表、记忆队列、关系网需要从零构建
  - 背景NPC: 从势力配置文件加载 ✓
  
  ⚠️ 逻辑缺口 #3: V2→V3迁移后NPC的"历史记忆"断裂
  
  V2存档中的NPC可能已经与玩家有丰富的互动历史(存在MemOS中)。
  迁移到V3后:
  - MemOS中的历史交互文本保留 ✓
  - 但NPC的记忆队列初始为空 → 第一条记忆是"迁移完成"标记
  
  NPC"记得"MemOS中的事(如果玩家询问，MemOS检索能返回)，
  但NPC行为系统的记忆队列中没有任何记录。
  
  这造成一个短期的叙事不连贯: 
  NPC对玩家的好感度是延续的(+45, 熟悉)，但NPC"不记得"为什么。
  
  解决方案: 迁移时从MemOS中提取最近的交互，生成初始记忆队列。
  但NPC文档未定义此迁移逻辑。

Step 3: 迁移后的首个每日结算
  世界规则引擎从第1天开始(或从V2存档的游戏天数继续?)
  
  ⚠️ 逻辑缺口 #4: 迁移后游戏时间的连续性
  
  V2存档可能已进行到第45天。V3.0启动后:
  - 游戏时间从第45天继续? → 世界规则引擎从第45天开始结算
  - 还是从第1天重新开始? → 丢失V2的45天叙事积累
  
  如果从第45天继续，世界规则引擎和NPC系统
  需要立即追赶45天的模拟状态——这是不可能的(初始状态是第1天的配置)。
  
  建议: 迁移后游戏时间重置为第1天(标注为"新纪元")，
  使用配置文件中的势力初始状态。
  玩家保留自身状态和NPC关系(好感度、记忆)，但世界"重新开始"。
```

### 本场景结论：发现 2 个运行时逻辑缺口

## 四、场景GG：零全局事件状态 — 世界完全静止

### 预设状态

```
某日结算后:
  所有活跃全局事件: 0个(上一个事件刚好到期消退)
  无阈值触发(所有势力状态正常)
  无冲突触发(无敌对势力相邻)
  无AI评估产生的新事件
  
  结果: 世界规则引擎Step 5(事件传播)和Step 6(阈值处理)均为空操作
  仅Step 1-4的基础资源更新和冲突判定(无冲突)
```

### 步骤追踪

```
Step 1: 零事件日的模拟层产出
  WorldStateUpdate仅包含:
    - 资源变更(食物-120, 水-120, 医疗-50... 全是确定性数值更新)
    - 无冲突结果
    - 无事件变更
    - 无AI评估结果
  → NPC系统收到一个"什么大事都没发生"的推送
  
Step 2: 叙事Agent的挑战
  玩家在下一个行动后，叙事Agent需要生成叙事。
  但模拟层没有提供任何"事件"作为叙事素材。
  
  叙事Agent基于:
    - ActionResult(玩家的行动结果)
    - WorldSnapshot(玩家自身状态)
    - 附近NPC状态
    - 记忆上下文
  
  即使世界层面无变化，这些个人层面的数据仍能支撑叙事。
  ✓ 设计合理: 叙事以玩家为中心，世界事件是"佐料"而非"主菜"

Step 3: 零事件持续时间
  世界规则引擎§2.3: 保底机制 minEventsPerDay 确保
  "全局每日最多N个"事件中N≥1(丧尸末日默认=1, 核战凛冬=0, 内战崩溃=1)
  
  核战凛冬的minEventsPerDay=0 → 可能连续多日零事件。
  这是设计意图(核战凛冬——世界已经死了，没有新事件发生)。
  在这种末日类型中，叙事重心完全转移到生存和环境描写。
  
  ⚠️ 逻辑缺口 #5: 核战凛冬的零事件状态下，叙事Agent缺少
  "环境主导叙事"的明确指令
  
  叙事Agent的System Prompt(§3.2)包含"五感描写"和"环境描写"——
  但这些是通用指令。在核战凛冬这种"世界已经死了"的设定中，
  叙事应更侧重"静默的绝望"——荒芜的风景、永不散去的辐射尘、
  幸存者的麻木。
  
  文档未定义不同末日类型的叙事风格差异。
```

### 本场景结论：发现 1 个运行时逻辑缺口

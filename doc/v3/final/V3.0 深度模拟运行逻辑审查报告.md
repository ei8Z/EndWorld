## 一、模拟方法论

构造四个端到端场景，在每个步骤追踪：

1. **谁触发** — 触发源是什么
2. **输入什么** — 数据从哪个模块、以什么格式传入
3. **做什么** — 执行什么计算或 AI 调用
4. **输出什么** — 输出到哪里，影响哪个模块
5. **时间消耗** — 每一步的现实时间和游戏时间

## 三、场景B：每日结算 — 多阈值同时触发

### 预设状态

```
游戏时间：跨过第5天午夜 → 第6天 00:00
势力状态（结算前）:
  红松幸存者营地: 人口120, 兵力30(25%), 食物储备360人口天(3天),
                  士气28, 控制区域3个(从6个减少)
  灰烬匪帮: 人口80, 兵力60(75%), 食物储备560人口天(7天), 士气70

触发: 红松营地同时跨过三个阈值 —
  食物储备：360/120=3天 → 危机 (触发: 势力食物危机)
  兵力：30/120=25% → 大于10%但需检查 → 警告 (触发: 势力兵力警告)  
  士气：28 → 警告 (触发: 势力士气警告)
```

### 步骤追踪

```
Step 1-5: 世界规则引擎确定性结算 (毫秒级)
  资源更新 → 状态检查 → 冲突判定 → 战斗结算 → 事件传播
  
Step 6: 阈值触发处理
  合并三个触发 → 组装AI请求（多触发格式）→ 调用轻量AI场景1 (Flash/low, 1-3s)
  
  ⚠️ 逻辑缺口 #1: AI异步执行期间的数据一致性问题
  
  Step 7 立即输出确定性 WorldStateUpdate（不含AI结果）并推送到NPC系统。
  NPC系统收到推送后启动结算，此时场景1的AI评估尚未完成。
  
  问题：NPC系统在结算时读取的世界状态不包括AI即将做出的变更。
  例如：AI可能判定红松营地"转变为掠夺模式" → 势力目标变为"掠夺"，
  但NPC系统在AI结果返回前已经完成了结算 → NPC的行为决策基于旧目标"防守"。
  
  影响链：
    NPC结算 → NPC间互动基于旧势力目标 → 
    场景1 AI返回 → 势力目标变更为"掠夺" →
    NPC的行为与势力新目标不一致，直到下一个每日结算才纠正。
  
  严重度：中等。影响仅限于"同一结算周期内NPC行为与AI决定的势力方向
  存在1个游戏日的偏差"。在末日世界叙事中，1天的延迟是可接受的。
  但文档未声明这一偏差的存在。

Step 7: WorldStateUpdate 输出（确定性部分立即，AI结果2-10s后异步追加）
  推送 → NPC行为系统启动结算

NPC系统结算:
  ⚠️ 逻辑缺口 #2: 需求过载致死判定在批量场景中失效
  
  假设NPC "商人王二" 状态：食物需求当前值50。
  每日结算推进24小时 → 食物需求+120 → 50+120=170 → clamp到100。
  
  第一次结算后：需求=100（第1天饱和）
  第二次结算后：需求=100（第2天饱和）
  第三次结算后：需求=100（第3天饱和） → 触发"连续3日饱和"死亡判定。
  
  问题出在加速模式批量追赶时。假设玩家加速3天：
  
  加速开始时王二食物需求=50。
  批量追赶一次性推进3×24小时=72小时的需求量：
    50 + (120×3) = 410 → clamp到100。最终值=100。
  
  但系统只知道"最终值是100"，无法判断已经连续饱和了多少天。
  如果在正常逐日结算中：
    第1天：50+120=170→100（饱和）
    第2天：100+120=220→100（饱和）
    第3天：100+120=220→100（饱和）→ 触发死亡 ✓
  
  在批量追赶中：
    只看最终状态=100 → 不知道是否连续3天饱和 → 
    如果系统保守处理（不杀）→ NPC永远不会因加速中的需求过载死亡
    如果系统激进处理（只要最终=100就判定死亡）→ NPC在加速1天后也可能死
  
  NPC文档未定义批量追赶下的需求过载致死判定逻辑。

  严重度：高。直接影响NPC生死——要么所有NPC在加速中免疫饥饿，
  要么加速一天就大量死亡。需要明确定义批量追赶下的连续饱和判定规则。
```

### 本场景结论：发现 2 个运行时逻辑缺口

## 场景D：战斗伤亡 → 关键NPC死亡判定

### 预设状态

```
每日结算 Step 3-4: 红松营地 vs 灰烬匪帮
红松: 兵力30, 单位战力1.0
匪帮: 兵力60, 单位战力1.2

兰彻斯特计算:
  ⚠️ 逻辑缺口 #5: 兰彻斯特公式与直觉解释存在数值矛盾
```

### 公式验证

```
文档公式:
  战斗力A = (兵力A)² × 单位战力系数A
  战斗力B = (兵力B)² × 单位战力系数B
  战力比 = 战斗力A / 战斗力B
  
  若战力比≥1 (A占优):
    A战损比例 = √(1/战力比)
    B战损比例 = √(战力比)

文档直觉解释:
  "战力比=2:1 → 强者战损约30%，弱者战损约70%"
  "战力比=4:1 → 强者战损约50%，弱者几乎全灭"

数值验证:
  战力比=2 (A是B的2倍强):
    公式: A战损 = √(1/2) = 0.707 = 70.7%
    直觉: 强者战损约30%
    矛盾！公式给出70.7%，直觉说30%

  战力比=4 (A是B的4倍强):
    公式: A战损 = √(1/4) = 0.500 = 50%
    直觉: 强者战损约50%
    一致 ✓
    B战损 = √4 = 2.0 = 200%（>100%意味着全灭）
    直觉: "弱者几乎全灭" ✓（概念一致但数值溢出）

  战力比=0.5 (B是A的2倍强，即战力比<1):
    此时B占优。但公式的"若战力比≥1"分支不适用。
    文档未定义战力比<1时的计算公式！
    
    如果交换A和B的角色（谁占优谁套用√(1/战力比)），则:
    实际优势方(B)战损 = √(1/(1/0.5))? 这需要明确定义。

结论: 战力比=2:1时的数值存在严重矛盾。70.7%与30%的差异会导致
战斗结果完全不同——按照公式，优势方损失惨重(70%)；按照直觉，
优势方轻松取胜(30%)。这直接影响CasualtyReport的规模、NPC死亡数量、
以及后续的场景3 AI评估触发频率。
```

### 继续追踪（使用直觉数值）

```
假设使用直觉数值（与实际游戏平衡更相关）:
  红松兵力30×1.0=30战力, 匪帮兵力60×1.2=72战力
  战力比 = 72/30 = 2.4（匪帮占优）
  匪帮(强者)战损 ≈ 35% → 损失21人
  红松(弱者)战损 ≈ 80% → 损失24人

  CasualtyReport:
    casualties: [background×20, 哨兵老张]  ← 溢出规则触发: 背景NPC不足
    survivors: [领袖李队长, 商人王二, ...]
    newInjuries: [{李队长, 中度伤}, {王二, 轻伤}]

  哨兵老张是接触NPC(战斗人员, 非关键NPC) → 直接标记死亡，不触发场景3。
  
  如果被抽中的是李队长(关键NPC, 领袖):
    Step 1: 检查剧情管理器 → 李队长未在关键剧情节点中注册
    Step 2: 触发轻量AI场景3
    Step 3: AI输入: 好感度+45(熟悉), 战斗角色:领袖, newInjuries:中度伤
    Step 4: AI判定 → outcome:"spare", narrativeHint:"他被部下拖离了战场"
    Step 5: NPC系统标记李队长为"重伤"而非"死亡"
    Step 6: 触发场景4(生存状态突变——重伤)
    
    ⚠️ 逻辑缺口 #6: 场景3和场景4可能在同一次结算中连锁触发
    
    场景3判定李队长"spare但severe_injury" → 
    这本身就是"重伤" → 满足场景4的触发条件。
    
    但场景4是NPC系统在结算期间触发的，而此时场景1的AI可能还在异步执行。
    场景3和场景4之间是否需要等待？场景4的AI调用是否应该在场景3完成后再触发？
    
    如果场景3 AI判定"spare但重伤"后，场景4立即触发并调用AI，
    那么场景4的AI输入中是否包含场景3的判定结果？
    
    当前文档未定义场景间连锁触发的处理顺序。
```

### 本场景结论：发现 2 个运行时逻辑缺口

## 六、其他运行时观察（非缺口但值得注意）

### 观察1：首次调用的 KV Cache 冷启动

裁决Agent System Prompt 约3000-4000 tokens（Agent §2.2描述）。玩家首次行动时，KV Cache未建立，输入token全额计费+延迟更高。随后的调用复用Cache。但文档未提及首次调用的预期延迟差异。

### 观察2：模板引擎"预期变化"的静态性

ExpectedChanges 在加速开始时计算一次，整个加速期间不变。如果玩家加速跨越数天，第1天计算的 "食物仅够维持4天" 到第3天可能已经过时——但模板仍显示4天。这是设计权衡，但可能在长加速中产生明显的数据不一致感。

### 观察3：场景5（罕见互动）的触发频率

NPC间互动每游戏日判定一次（NPC §4.3），每次判定涉及同一Location内的所有NPC对。如果有20个接触NPC在同一Location，可能的NPC对数量为 C(20,2)=190对。每对至少有50%概率触发互动（日常社交）。在190对互动中，任何一对满足"涉及关键NPC"或"道德困境"条件都会触发场景5。在最坏情况下，一次每日结算可能触发数十次场景5调用——虽然降级策略§5.12有连续5次暂停机制，但首次触发时没有频率限制。

## 七、与七轮文档审核的关系

前七轮审核（48个问题）检查的是"文档之间是否一致"。本轮检查的是"文档描述的系统实际运行时会发生什么"——这是正交维度。例如：
- 兰彻斯特公式在文档间完全一致（Agent未引用该公式，仅世界规则引擎定义），但公式本身存在数值矛盾
- 需求过载致死在所有文档中定义一致，但批量追赶场景下逻辑不可行

这些问题无法通过文档对比发现，只能通过运行时模拟暴露。

## 一、场景J：减速（子弹时间）模式 — 完整战斗序列

### 预设状态

```
游戏时间：第7天 16:00
玩家：HP 72, 装备: 手枪(耐久85%), 附近NPC: 敌对匪徒×3(背景NPC)
速度档位：减速（现实1秒 = 游戏内3秒）
```

### 步骤追踪

```
Step 1: 玩家选择"减速"元行动 → 世界时间流速切换为1:3
        ↓
Step 2: 叙事Agent生成子弹时间叙事（更高密度的感官细节）
        V3.0总纲§3.4: "叙事Agent的叙事密度增加（更多感官细节、更细腻的动作描写）"
        suggestions: ["侧身闪避", "反击头部", "呼叫支援", "使用医疗包止血"]
        ↓
Step 3: 玩家选择 "反击头部"
        裁决Agent调用(Pro/max/8192, 8-20s)
        输入: RulingContext{playerAction{type:"反击", target:"头部", riskLevel:"高"}}
        
        ⚠️ 逻辑缺口 #1: 减速模式的DC判定基础值来源不明确
        
        V3.0总纲§3.4描述减速模式的suggestions为"秒级/分钟级选项"，
        但裁决Agent的System Prompt(§2.2)包含"基础DC选取"——
        这个DC值在减速模式下是否需要调整？
        
        正常模式: "反击"的DC可能基于对方的战斗能力和环境因素
        减速模式: 玩家有更多"反应时间"(游戏内时间流速慢)，
        理论上DC应略低(更容易成功)或DC不变但结果更精细?
        
        文档未定义减速模式对裁决Agent DC基准的影响。
        
Step 4: 裁决Agent返回ActionResult
        result:"部分成功", rollValue:15, dcValue:14, 
        narrativeSummary:"子弹擦过匪徒A的肩膀，他踉跄了一下但未倒下"
        ↓
Step 5: 叙事Agent生成减速模式叙事
        密度更高: 不是"你开枪击中匪徒"，而是
        "枪口焰火在昏暗中炸开，弹壳在空中旋转着坠落——
         匪徒A的肩膀炸开一朵血花，他踉跄后退，脸上的狞笑凝固为惊恐..."
         
        ⚠️ 逻辑缺口 #2: 减速模式叙事密度增加但maxTokens不变
        
        叙事Agent的maxTokens固定为8192(§3.1)。
        减速模式需要"更多感官细节"，但token预算相同。
        这意味着减速叙事需要更高的"信息密度"而非"更多字数"——
        AI需要在相同字数内写得更细腻。
        
        但Agent §3.2的System Prompt描述中没有区分正常/减速模式的
        叙事密度指令。AI需要从user message中推断当前模式。
        而user message的构建方法(§3.3)也没有提到传入速度档位信息。
        
        叙事Agent只知道自己收到了"玩家行动标签 + ActionResult"，
        不知道当前是正常模式还是减速模式。
        
Step 6: 玩家连续发出多个减速行动
        "侧身闪避"(消耗3秒游戏时间) → "瞄准匪徒B腿部"(2秒) → "射击"(1秒)
        
        每次行动: 裁决Agent(8-20s) + 叙事Agent(3-8s) = 11-28s 现实等待
        3次行动 × 11-28s = 33-84s 现实时间
        但只过了6秒游戏时间!
        
        V3.0总纲§6.1已声明此延迟:
        "减速模式（子弹时间）下延迟不变——玩家获得更细腻的叙事密度，
         但每次行动的 AI 等待时间相同。"
        
        这是已知设计权衡，非逻辑缺口。✓
```

### 本场景结论：发现 1 个运行时逻辑缺口

## 二、场景K：全局事件SIR传播 + 区域事件级联

### 预设状态

```
5个区域线性排列: A—B—C—D—E
区域C(玩家所在): 威胁等级30, 控制势力=红松
活跃全局事件: 尸潮(强度75, 源区域A, 已影响A和B, 剩余持续5天, 传播速率0.3)
```

### 逐日传播模拟

```
Day 1: 尸潮在A和B活跃
  传播到C: 概率=0.3×道路1.5(假设A-B-C为道路连接)×城市废墟1.2=0.54
  判定: 通过 → C加入受影响列表
  
  ⚠️ 逻辑缺口 #3: 事件传播到玩家所在区域时触发什么?
  
  世界规则引擎§3.4: "叠加时威胁等级累加，但不超过100"
  C的威胁等级: 30→30+75=105→clamp到100
  
  世界规则引擎§6.2: "世界事件抵达玩家所在区域时，世界规则引擎提供
  影响玩家所在区域的事件描述"
  
  NPC文档§4.2: 区域事件推送→NPC执行中断检查
  尸潮接近 → NPC前往安全区域或避难所
  
  但玩家呢? 玩家正在C区域。当前设计假设玩家在事件到达时"被通知"——
  但通知机制是什么? 是通过世界叙事Agent生成"事件广播"，
  还是通过叙事Agent在下一次行动叙事中提及?
  
  V3.0总纲§6.3说世界叙事Agent负责"世界事件广播"——
  但这仅在加速模式下。
  
  在正常模式下，玩家只有在发出下一个行动后才会收到叙事Agent的回复。
  如果玩家在C区域"等待"了数小时(正常模式，时间不自动推进)，
  尸潮已经逼近但玩家毫不知情——直到发出行动。
  
  这意味着: 在正常/减速模式下，全局事件传播到玩家所在区域时，
  没有主动通知机制。玩家只能通过下一次行动的叙事反馈间接得知。

Day 2: 尸潮在A、B、C活跃
  传播到D: 概率=0.3×0.8×1.0=0.24, 未触发
  传播到D(另一路径? 无): 仅相邻
  
  C区域NPC响应: 红松营地的接触NPC按性格响应
    老张(谨慎): 建议加强防御
    王二(自私): 开始囤积物资
    李队长(忠诚): 组织防御工事
    
  NPC间互动: 老张-李队长(合作: 防御准备, 好感度+10) ✓
  
  ⚠️ 逻辑缺口 #4: 全局事件强度衰减机制缺失
  
  尸潮从A传播到B再到C，强度始终是75。
  SIR模型中，事件在传播时强度不应保持不变——
  但世界规则引擎§3.4的事件属性中"强度"是固定值。
  
  传播3个区域后的尸潮和最初在A爆发的尸潮强度相同?
  这不合理——事件在传播过程中应逐渐减弱。
  
  如果事件在传播时强度衰减(如每个区域-10)，传播距离越远影响越小，
  更符合真实世界的灾害传播规律。

Day 3: 尸潮持续传播
  ⚠️ 逻辑缺口 #5: 事件消退后的"恢复"标签没有后续影响定义
  
  世界规则引擎§3.4:
  "受影响区域的状态标签更新（如'尸潮经过'改为'尸潮后恢复中'）"
  
  '尸潮后恢复中'标签会持续多久? 是否有任何机制效果?
  例如: 资源丰度是否逐渐恢复? 威胁等级是否逐渐降低?
  
  文档未定义"恢复中"状态的持续时间和效果。
```

### 本场景结论：发现 3 个运行时逻辑缺口

## 三、场景L：NPC降级 — 从关键NPC到接触再到背景的完整生命周期

### 预设状态

```
NPC: 商人王二(接触NPC, 好感度+25(熟悉), 互动次数: 8次)
当前时间: 第5天
上次互动: 第4天上午(距今1天)
```

### 生命周期追踪

```
Day 5-12: 玩家因主线剧情前往其他Region(Region_C→Region_D)
  王二留在红松营地，玩家连续8天未与王二互动

Day 7: 距上次互动超过7天
  提取衰减规则触发: "超过7天未互动的接触NPC，其'可被引用的后果'权重逐步降低"
  
  ⚠️ 逻辑缺口 #6: "权重逐步降低"的具体数值定义缺失
  
  NPC文档§2.2: "超过7天未互动的接触NPC，其'可被引用的后果'权重逐步降低"
  
  但"逐步降低"的速率是多少? 每天降低多少?
  权重从什么值开始，降到什么值结束?
  这个模糊定义在实现时会导致:
  - 实现者自行选择一个衰减函数(线性/指数)
  - 不同实现可能导致NPC降级速度差异巨大

Day 12: 玩家返回红松营地
  王二仍在接触层(降级检查在Day 30)
  好感度仍为+25，但缺乏近期互动记忆
  玩家的叙事中"你认出了商人王二，但感觉有些生疏了"
  
  ⚠️ 逻辑缺口 #7: NPC在无互动期间的自主生活
    
  王二在玩家离开的8天中经历了8次每日结算:
  - 8×24h的需求推进 → 可能触发需求驱动行为
  - 与其他NPC的互动(NPC间互动每游戏日判定)
  - 可能的外出探索
  
  这些变化都会写入王二的状态:
  - 需求值变动
  - NPC间好感度变化
  - 社交快照(记忆)
  
  但对玩家而言，王二的变化是不可见的——除非主动询问。
  裁决Agent在玩家与王二再次互动时，会收到王二的"当前状态"和"近期记忆"，
  但玩家在互动前不知道王二经历了什么。
  
  这本身是设计意图("世界在玩家不行动时继续运转")，
  但文档未说明: 当玩家与"久别重逢"的NPC互动时，
  裁决Agent的RulingContext中应特别标记"距上次互动天数"，
  以便叙事Agent在叙事中体现时间流逝感。

Day 30: 连续30天无互动(假设玩家再次长期离开)
  降级检查触发: 王二非关键NPC, 无未完成的承诺 → 降级为背景NPC
  
  降级处理:
  - 王二的结构化数据存档(好感度+25, 记忆摘要)
  - 群体标签更新: 红松营地背景NPC"对玩家态度"更新
  - 但王二的"个体身份"消失 → 他变成了"红松营地的商人们"之一
  
  ⚠️ 逻辑缺口 #8: 降级NPC的"再提取"规则缺失
  
  如果玩家再次与背景NPC互动(如"向红松营地的商人们打听物资信息")，
  而王二恰好在其中。玩家再次与王二产生"可被引用的后果" → 触发提取。
  
  再提取时:
  - 应从存档中恢复王二之前的好感度(+25)和记忆摘要吗?
  - 还是完全创建一个"新"接触NPC(好感度从群体态度基准值开始)?
  
  如果完全新建 → 玩家之前与王二的互动历史全部丢失 → 叙事不连贯
  如果恢复存档 → 王二"重新出现"在接触层，带着历史记忆 → 叙事有连续性
  
  文档未定义降级NPC再提取时的初始化规则。
```

## 五、场景N：所有势力同时覆灭的极端边界

### 预设状态

```
极端假设: 一场超级灾难事件同时影响所有势力
势力A(红松): 兵力0(已在上次战斗全灭), 食物0
势力B(匪帮): 兵力5(从60降至5), 食物仅够1天
势力C(蓝河): 兵力3(从40降至3), 食物0

无主区域: Region_A, Region_C
唯一存续势力: 匪帮(濒临覆灭)
```

### 步骤追踪

```
Step 1: 每日结算
  红松: 食物0 → 触发极端资源状态处理(第一次深度模拟修复)
        → 势力解散判定 → AI评估解散后果
  匪帮: 兵力5/80=6.25% → 跨过兵力危机阈值(<5%)?
        5/80=6.25%, 大于5%! 微妙地未触发兵力危机。
        但食物仅够1天 → 触发食物危机
        
  ⚠️ 逻辑缺口 #11: 所有势力濒临覆灭时，AI评估缺少参照系
        
  正常情况: 势力A食物危机 → AI评估"是否向势力B求援"
  但当所有势力都处于危机中时:
  - 红松正在解散(无法求援)
  - 蓝河食物归零(自身难保)
  - 匪帮食物仅1天(即将步入红松后尘)
  
  场景1的AI评估输入中包含"周边势力"——
  但AI会看到所有周边势力都处于危机中。
  System Prompt §5.3原则#3说"选择最保守的选项"——
  在这种全局崩溃的场景下，"最保守的选项"是什么?
  
  没有人可以求援，没有人可以掠夺(兵力不足)，没有人可以迁移(无处可去)。
  AI可能输出"维持现状"——但这等于坐等灭亡。
  
  这种全局崩溃场景本身是末日世界的可能结局——
  但AI评估的设计假设是"总有一个合理的反应方向"，
  在全局崩溃时这个假设不成立。

Step 2: 势力覆灭后的区域归属真空
  
  红松解散 → Region_A变为无主
  蓝河食物归零 → 触发解散判定 → Region_C变为无主
  匪帮食物1天 → 次日也将解散
  
  三个相邻区域全部变为无主。
  
  世界规则引擎§3.2: "无主区域自动被相邻势力的最强方'宣称'"
  但如果所有相邻势力都解散了 → 没有势力可以宣称 → 
  所有区域永久无主?
  
  ⚠️ 逻辑缺口 #12: 全局势力真空后的新势力生成机制缺失
  
  世界规则引擎§2.3事件产生规则中:
  "AI评估产生: AI评估输出中包含newEntities或建议的新事件"
  
  但AI评估是在势力解散时触发的——如果所有势力都解散了，
  最后一个解散的势力的AI评估可能建议"新势力出现"。
  但"新势力"的初始状态是什么? 人口从哪来? 资源从哪来?
  
  场景1的newEntities字段允许AI建议新增势力，
  但文档未定义newEntities的初始属性生成规则
  (人口数、资源池初始值、控制区域、武装程度等)。
```

### 本场景结论：发现 2 个运行时逻辑缺口

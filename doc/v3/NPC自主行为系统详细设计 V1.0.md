# NPC自主行为系统详细设计 V1.0

**所属项目**：末日求生 · AI叙事游戏 V3.0
**模块定位**：模拟层核心——管理NPC的自主行为、记忆与关系
**设计原则**：规则驱动为主，轻量AI增强为辅，分层管理
**依赖模块**：世界规则引擎（弱依赖——MVP阶段可用桩数据替代每日结算推送，仅区域事件响应§4.2和区域状态变更§7.1需要真实数据）


## 一、模块职责

NPC自主行为系统是V3.0模拟层的第二个核心组件。它负责让NPC在玩家不在场时也有自己的生活，让玩家再次相遇时能感受到时间流逝和关系变化。

**它做什么**：
- 管理NPC的时间表与日常节奏
- 驱动NPC基于需求做出行为选择
- 维护NPC对玩家的记忆与情感演变
- 处理NPC之间的互动
- 管理NPC的进入、离开与归来
- 向叙事层提供NPC当前状态

- **它不做什么**：
- 不生成叙事文本（由叙事Agent负责）
- 不模拟背景NPC的个体行为（背景NPC由世界规则引擎的群体标签管理）
- 不处理玩家行动的直接后果（由裁决Agent负责）


## 二、NPC三层结构

### 2.1 分层定义

**第一层：背景NPC（数十到数百个）**

不维护个体数据，只维护群体标签。由世界规则引擎管理。

群体标签结构：
- 所属场景/势力
- 大致人数
- 群体士气（0-100）
- 群体状态（如“最近伤亡3人”、“食物充足”）
- 对玩家的群体态度（欢迎/中立/警惕/敌意）

玩家与背景NPC互动时，若不满足提取条件，则只更新群体标签。若满足提取条件，则从中“提取”一个具体NPC进入第二层。

**第二层：接触NPC（预计10-30个）**

玩家直接交互过、且互动产生了“可被引用的后果”的NPC。

拥有完整的个体数据：性格标签、需求、记忆、时间表、好感度。

NPC行为系统的核心管理对象。所有接触NPC在每游戏日结算时更新状态。

**第三层：关键NPC（预计3-5个）**

与玩家有深度关系或对剧情有重大影响的NPC。

在第二层基础上增加：
- 更复杂的记忆结构（详细记忆队列扩展为5条）
- 情感演变轨迹（关系阶段追踪：陌生人→熟悉→信任→亲密/破裂）
- 自主决策能力（可选择使用轻量AI增强其行为真实感）
- 与其他关键NPC的关系网
- 
### 2.2 提取规则：从背景到接触

当玩家与背景NPC的互动产生“可被引用的后果”时，该NPC从背景层提取到接触层。

提取条件（满足任一即触发）：
- 好感度变化绝对值 ≥ 10
- 产生了承诺（NPC要求玩家做某事，或玩家要求NPC做某事）
- 发生了物品转移（给予或接受）
- NPC向玩家透露了独特信息（情报、秘密、个人背景）

不触发提取的情况：
- 礼节性对话（“你好”、“今天天气不错”）
- 单方面观察（“我看了一眼士兵们”）
- 无后果的群体交流（“我向哨卡的士兵们点了点头”）

触发提取时，系统即时创建一个接触NPC实例，赋予基础属性：
- 从群体标签中推断性格标签（随机分配或根据场景预设）
- 初始好感度基于互动结果
- 初始需求随机分配
- 默认时间表基于其身份和所在场景
- 记忆队列初始化为空，第一条记忆记录本次交互

**提取衰减规则**：
提取条件的权重随时间衰减，防止过时的互动永久占用接触NPC配额：
- 超过7天未互动的接触NPC，其"可被引用的后果"权重逐步降低
- 连续30天无互动 → 触发降级检查：若该NPC非关键NPC且无未完成的承诺，降级为背景NPC
- 降级时，NPC的结构化数据存档（保留好感度和记忆摘要），在群体标签中更新"对玩家态度"

### 2.3 关键NPC的判定标准

以下条件满足任一，接触NPC升级为关键NPC：
- 好感度达到80以上或降至-50以下
- 与玩家互动超过10次
- 在剧情管理器中注册为关键剧情角色
- 玩家主动标记（如选择“这是我可以信任的人”）


## 三、NPC核心属性

### 3.1 基础信息

- NPC ID：唯一标识
- 姓名：显示文本
- 身份：如“哨卡士兵”、“流浪商人”、“势力领袖”
- 所在场景/势力：当前位置或所属势力
- 性格标签：如“谨慎”、“慷慨”、“多疑”、“勇敢”、“自私”
- 状态标签：如”受伤”、”饥饿”、”士气低落”、”心怀感激”

### 3.1.1 势力-区域-NPC 关联模型

为避免三份文档中势力/区域/NPC的映射关系模糊，明确定义三者层级：

```
世界规则引擎管理                      NPC行为系统管理
┌─────────────────┐                ┌─────────────────┐
│ 势力(Faction)    │──控制────────→│ 区域(Region)     │
│ · 资源池         │                │ · 威胁等级       │
│ · 兵力/士气      │                │ · 资源丰度       │
│ · 控制区域列表   │                │ · 包含多个场景    │
└─────────────────┘                └────────┬────────┘
                                            │ 包含
                                            ▼
                                ┌─────────────────┐
                                │ 场景(Location)   │
                                │ · NPC可位于此    │
                                └────────┬────────┘
                                         │ 位于
                                         ▼
                                ┌─────────────────┐
                                │ NPC             │
                                │ · 所属势力=所在  │
                                │   区域的控制势力  │
                                │   (默认，可覆盖) │
                                └─────────────────┘
```

**关联规则**：
- 一个 Region 包含多个 Location（场景）。NPC 位于某个 Location
- NPC 的”所属势力”默认为其所在 Region 的 ControlFaction，但可被覆盖（如流浪商人无势力归属）
- NPC 跨 Region 移动时：原势力人口-1，目标 Region 势力人口+1
- 背景NPC的群体标签绑定在 Region 级别，由世界规则引擎管理

### 3.2 时间表

每个接触NPC维护一个精确的时间段-位置映射：

**时间表结构**：时间段标签 → 位置ID

**预设时间段**：
- 清晨（5:00-8:00）
- 上午（8:00-12:00）
- 下午（12:00-17:00）
- 傍晚（17:00-20:00）
- 夜晚（20:00-5:00）

**时间表生成**：
- NPC实例化时根据其身份自动生成默认时间表
- 时间表可因事件临时覆盖（见第五节）

**时间表异常处理**：
NPC出现在非预期位置时，视为异常，需要触发解释机制：
- 系统生成一个简短的结构化说明（如“听到枪声前来查看”、“被上级临时调派”）
- 若该异常对剧情有重大影响，升级为轻量AI评估
- 异常解除后，时间表恢复正常

### 3.3 需求系统

每个NPC维护一组需求，每个需求有紧迫度评分（0-100）。

> **结算频率**：需求紧迫度在每游戏日结算时一次性推进24小时（与V3.0总纲§3.5对齐）。行为决策在每日结算时统一判定，消除"需求触发"与"行为响应"之间的时间差。

**需求类型及基础权重**：

| 需求类型 | 权重 | 紧迫度日增量 | 等效小时速率（仅供参考） |
|----------|------|-------------|------------------------|
| 生存-食物 | 最高 | +120/游戏日 | （等效+5/小时） |
| 生存-饮水 | 最高 | +192/游戏日 | （等效+8/小时） |
| 生存-医疗 | 最高 | 受伤时+360/游戏日 | （等效+15/小时） |
| 安全 | 高 | 区域威胁>50时+240/游戏日 | （等效+10/小时） |
| 社交 | 中 | 生存和安全满足时+72/游戏日 | （等效+3/小时） |
| 自我实现 | 低 | 其他需求满足时+24/游戏日 | （等效+1/小时） |

> **与玩家消耗速率差异说明**：NPC的需求增长速度约为玩家的1.7~2倍。设计意图——NPC没有玩家的"背包管理"优势，物资获取效率更低，在末日环境中面临更严峻的生存压力。这一差异是有意为之，用于驱动NPC主动向玩家求助或交易。

**需求驱动行为**：
NPC的当前行为倾向由紧迫度最高的需求决定：
- 生存需求最高 → 寻求交易、求助、自行搜索物资
- 安全需求最高 → 加强防御、减少外出、依赖信任的人
- 社交需求最高 → 主动交谈、寻求陪伴、表达情感
- 自我实现最高 → 尝试领导、主动探索、帮助他人

**需求满足**：
- 食物需求：进食后归零，饱食度满后锁死24游戏小时
- 饮水需求：饮水后归零
- 医疗需求：接受治疗后归零
- 安全需求：区域威胁下降后逐步降低
- 社交需求：有意义的社交互动后归零
- 自我实现：完成个人目标后归零

### 3.4 记忆系统

**记忆队列结构**：最近N条详细记忆 + 远期摘要

| NPC层级 | 详细记忆队列容量 | 压缩为摘要的时机 |
|---------|-----------------|-----------------|
| 接触NPC | 3条 | 第4条记忆加入时，最旧的一条压缩 |
| 关键NPC | 5条 | 第6条记忆加入时，最旧的一条压缩 |

**详细记忆条目**：
- 时间戳
- 地点
- 交互摘要（一句话描述）
- 情感变化（好感度变化值+情感倾向标签）

**远期摘要**：
由被压缩的详细记忆合并而来。当多条详细记忆被压缩时，合并为一句话概括（如“玩家曾多次帮助我寻找物资，但有一次因故未能兑现承诺”）。

**记忆检索优先级**：
1. 首先检索详细记忆（匹配当前情境）
2. 其次检索远期摘要（补充背景）
3. 最后检索MemOS中的交互文本（补充叙事细节，非结构化）

### 3.5 情感系统

**好感度**：-100到+100

> **与现有代码的兼容说明**：当前 V2.x 代码中 `NpcRelation.affinity` 使用 0~100 范围（百分比语义）。V2.6 实现时需做数据迁移：`newAffinity = (oldAffinity - 50) * 2`，将现有存档中的好感度映射到新范围。同步更新 `NpcUpdate.affinityDelta` 的语义文档。

**关系阶段**：

| 好感度范围 | 关系阶段 | 说明 |
|-----------|---------|------|
| -100 ~ -60 | 仇恨 | NPC主动与玩家为敌 |
| -60 ~ -20 | 敌意 | NPC不信任玩家，可能设防 |
| -20 ~ +20 | 中立/陌生 | 初识或冷淡 |
| +20 ~ +50 | 熟悉 | NPC认识并接受玩家 |
| +50 ~ +80 | 信任 | NPC愿意透露个人信息，接受委托 |
| +80 ~ +100 | 亲密 | NPC主动提供帮助，可托付重要任务 |

**阶段跨越**：
当好感度跨越关系阶段边界时，触发特殊处理：
- 记录跨越事件（用于叙事Agent生成“关系质变”叙事）
- 更新NPC的行为模式（如从“警惕”变为“开放”）
- 若跨越涉及关键NPC，触发轻量AI评估

**情感倾向标签**：附加情感描述，如“感激”、“失望”、“亏欠”、“敬佩”、“恐惧”。一个NPC可同时有多个情感倾向标签，但只展示最强的2-3个。


## 四、NPC自主行为机制

### 4.1 日常行为驱动

NPC的日常行为由时间表+需求共同驱动。

**行为优先级**：
1. 生存需求（饥饿/口渴/受伤）→ 覆盖时间表，优先满足
2. 安全需求（区域威胁骤升）→ 覆盖时间表，寻找安全
3. 时间表常规行为
4. 社交/自我实现需求（在前三项满足后浮现）

**需求中断规则**：
当NPC在执行时间表行为时，若更高优先级需求触发：
- 当前行为终止
- NPC转向满足紧急需求
- 记录中断事件（供叙事Agent使用）

### 4.2 区域事件响应

当世界规则引擎推送区域状态变更时，NPC行为系统执行“中断检查”。

**事件→行为映射表**：

| 区域事件 | NPC默认行为 |
|----------|------------|
| 尸潮接近 | 前往安全区域或避难所 |
| 势力冲突 | 躲避或参战（取决于NPC身份和性格） |
| 资源发现 | 前往探索（若NPC有此需求） |
| 天气骤变 | 寻找庇护所 |
| 势力撤离 | 跟随撤离或留下（取决于NPC对势力的忠诚度） |

**性格对响应的影响**：
- 勇敢型：冲突时倾向参战，灾难时倾向帮助他人
- 谨慎型：冲突时倾向躲避，灾难时优先自保
- 自私型：资源发现时抢先行动，灾难时不帮助他人
- 忠诚型：跟随势力决定，维护势力利益

### 4.3 NPC间互动

**结算时机**：
- 每游戏日结束时
- 玩家离开一个场景时
- 世界规则引擎推送区域状态变更时

**互动判定**：
在结算点，检查同一场景内的NPC对（或同一势力的NPC对），根据条件判定是否发生有意义的互动。

**互动类型与触发条件**：

| 互动类型 | 触发条件 | 结果 |
|----------|----------|------|
| 日常社交 | 任意两个NPC同场景，概率50% | 好感度微调（±5） |
| 资源分享 | 一方有需求，另一方有资源 | 需求方需求降低，给予方好感度+10 |
| 争执 | 双方需求冲突（如同一资源） | 双方好感度-10，可能影响群体士气 |
| 合作 | 共同面对威胁或共同目标 | 双方好感度+10，合作成果体现 |
| 关系破裂 | 好感度持续下降跨过阈值 | NPC可能离开场景或势力 |

**互动粒度**：
常规互动只记录结果（数值变更），不模拟过程。以下罕见情况触发轻量AI评估：
- 涉及关键NPC
- 互动可能导致NPC死亡或永久离开
- 互动涉及道德困境（背叛、牺牲、重大承诺）
- 互动可能显著改变势力内部结构

### 4.4 NPC的离开与归来

**离开判定**：每游戏日结算时，基于以下条件判定：

| 离开原因 | 触发条件 | 结果 |
|----------|----------|------|
| 死亡 | NPC受伤且未获得医疗，或所在场景遭遇灾难 | NPC被标记为已死亡 |
| 迁移 | 所属势力撤离，或区域威胁等级过高 | NPC迁移至新场景/势力 |
| 外出探索 | NPC需求驱使其外出（如寻找物资） | NPC暂时离开，预期归来时间≤3游戏日 |
| 关系破裂 | 对玩家好感度跨过仇恨阈值，或与势力内多数人不和 | NPC永久离开，可能加入敌对势力 |
| 被驱逐 | 违反势力规则，或被势力领袖判定为威胁 | NPC被标记为被驱逐 |

**归来机制**：
当NPC标记为”外出探索”且归来时间到达时：
- NPC重新出现在原场景
- 更新状态（探索结果：可能带回物资、受伤、或空手而归）
- 记录归来事件

**外出超时处理**：
- 最大外出时长 = 3游戏日
- 超时未归 → 标记为”失踪”，触发轻量AI评估判定结果：死亡/被俘/加入其他势力/重伤返回
- 失踪NPC的接触层数据保留7天（等待可能的AI评估结果），超期则降级为背景NPC

**对叙事层的影响**：
玩家到达场景时，系统提供该场景应有的NPC列表及状态摘要：
- 谁在场
- 谁不在了（及原因）
- 谁是新的（背景NPC被提取或外来NPC）


## 五、时间表中断处理

### 5.1 中断类型

**临时中断**：因事件临时改变位置，事件结束后恢复时间表。
- 触发源：区域事件、玩家互动、NPC间互动
- 持续时间：事件持续期间
- 处理：记录当前时间表位置，事件结束后恢复

**永久调整**：因状态质变导致时间表长期变更。
- 触发源：需求长期得不到满足、势力归属变更、角色身份变化
- 处理：生成新时间表，旧时间表存档

### 5.2 中断时的解释机制

当NPC出现在非预期位置时，系统为该异常生成解释：

**轻度异常**（临时中断，持续时间<1游戏日）：
- 系统自动生成简短的结构化说明（如“因事件X临时在此”）
- 不需要AI调用
- 提供给裁决Agent，用于叙事中的一句话解释

**重度异常**（永久调整，或异常原因复杂）：
- 触发轻量AI评估
- AI输出异常的原因和影响
- 提供给叙事Agent，用于生成更详细的叙事


## 六、与MemOS的协作

### 6.1 存储职责划分

| 数据类型 | 存储位置 | 说明 |
|----------|----------|------|
| NPC结构化数据 | NPC行为系统（本地数据库） | 时间表、需求、好感度、记忆摘要、关系网。权威数据源。 |
| 玩家-NPC交互文本 | MemOS | 交互时的叙事片段、AI生成的交互摘要。非结构化补充记忆。 |
| NPC间互动结果 | NPC行为系统（本地数据库） | 纯结构化数据，不入MemOS。 |

### 6.2 检索协调

当玩家与NPC再次相遇时：
1. NPC行为系统提供该NPC的精确结构化状态（好感度、当前需求、最近记忆摘要、关系阶段）
2. MemOS检索与该NPC相关的历史叙事片段
3. 裁决Agent和叙事Agent接收两者结合的信息

**优势**：
- NPC的客观状态精确可查（不受记忆噪声影响）
- MemOS的叙事检索保留交互的文学细节
- 两者互补，而非互相替代


## 七、与V3其他模块的交互

### 7.1 接收：来自世界规则引擎

世界规则引擎每日结算后，向NPC行为系统推送：
- 当前区域的状态变更（威胁等级变化、控制势力变化）
- 全局事件影响（该NPC所在区域是否被事件波及）
- 所属势力的状态变更（食物短缺、士气下降、势力迁移）

NPC行为系统据此更新NPC的状态、需求和位置。

### 7.2 输出：向裁决Agent和叙事Agent

当玩家与NPC交互时，NPC行为系统提供：

**静态信息**（每次交互都提供）：
- NPC姓名、身份、性格标签
- 与玩家的关系阶段和好感度

**动态信息**（仅在变化时提供）：
- NPC当前需求（如果与上次见面不同）
- NPC最近经历的重要事件（如果与玩家相关或影响NPC状态）
- NPC对玩家的情感倾向（如果有变化）
- NPC的异常位置解释（如果触发）

### 7.3 与剧情管理器的协调：冻结/解冻协议

剧情管理器优先级高于模拟层。当关键剧情节点涉及特定NPC时，需冻结该NPC的自主行为。

#### SimulationFreeze 规范

剧情管理器在关键节点开始时，发出冻结请求：

```
SimulationFreeze {
  targetType: "npc" | "faction" | "region"
  targetIds: [...]
  freezeBehavior: "full" | "needs_only" | "position_only"
  maxFreezeDays: Int (超时自动解冻，默认3天)
}
```

- `full`：完全冻结——NPC的需求、位置、行为决策均不变化（用于关键对话、战斗场景）
- `needs_only`：仅冻结行为决策——需求值继续增长，但NPC不做反应（用于短期剧情）
- `position_only`：仅冻结位置——NPC不移动，但需求和低优先级行为继续（用于等待场景）

#### 解冻追赶规则

剧情节点完成后，PlotManager 调用 `thaw(targetIds)`：

- 若 `累计冻结天数 = 0`：无追赶，NPC从当前状态继续
- 若 `累计冻结天数 > 0`（仅 `needs_only` 和 `position_only` 模式积累）：执行批量追赶——一次性推进冻结期间的需求值，基于新状态判定是否需要立即触发行为

#### 协调优先级

- 剧情管理器可覆盖NPC的特定状态（如强制好感度变化、强制位置变更）
- 世界规则引擎的冻结由各自的模块独立管理（见世界规则引擎文档§6.4）
- NPC行为系统和世界规则引擎的冻结是独立的——可以只冻结NPC而不冻结势力


## 八、性能与复杂度控制

**NPC数量控制**：
- 接触NPC上限：30（超过上限时，最不活跃的接触NPC降级为背景NPC）
- 关键NPC上限：5
- 降级时，NPC的结构化数据存档，仅保留群体标签

**结算计算量**：
- 每游戏日遍历所有接触NPC一次
- 对于10-30个接触NPC，每次结算的计算量在毫秒级
- NPC间互动判定仅在同一场景的NPC对之间进行，进一步降低计算量

**AI调用频率**：
- 日常行为：零AI调用
- NPC常规互动：零AI调用
- 罕见情况（涉及关键NPC、生死、道德困境）：轻量AI调用
- 预计AI调用频率：每几个游戏日一次


## 九、开发建议

### 9.1 最小可行实现

首次实现建议只包含：
- 接触NPC（不区分关键NPC）
- 基础时间表（固定模板，按身份分配）
- 两个需求（食物、安全）
- 好感度系统和关系阶段
- 记忆队列（3条详细记忆）
- 基础的NPC间互动（仅日常社交和资源分享）
- NPC离开与归来（仅死亡和迁移）

这个最小版本可在3-4天内实现，足以验证NPC行为系统的核心循环。

### 9.2 渐进扩展

验证通过后逐步加入：
- 关键NPC特殊待遇
- 完整需求系统（五个需求维度）
- 复杂NPC间互动（争执、合作、关系破裂）
- 时间表中断处理
- 轻量AI增强（用于罕见情况）
- 与MemOS的检索协调

### 9.3 调试工具

> **移动端适配**：本项目为 Android 应用，调试面板不建议内置于应用 UI 中。推荐方案：
> - 开发阶段使用 `adb logcat` 输出结构化 JSON 日志 + 桌面端可视化脚本解析
> - 或使用 Android Debug Bridge 转发到本地 Web 调试面板
> - 关键状态变更（罕见情况触发、NPC降级/升级、关系阶段跨越）写入 Room DB 的调试日志表

调试功能清单：
- 显示所有接触NPC列表（含层级的筛选）
- 查看单个NPC的完整状态（时间表、需求、记忆、关系）
- 模拟时间推进，观察NPC状态变化
- 记录罕见情况触发日志

> 审查日期：2026-06-09
> 审查范围：V3.0 文档体系中对各类 AI Agent/调用的配置定义
> 对照基准：V2.x 代码中的实际 API 客户端实现

## 一、审查总览

V3.0 设计文档定义了四类 AI 调用点，但它们的配置定义处于三种不同的状态：

| Agent/调用 | 配置定义状态 | 问题数 |
|-----------|------------|--------|
| 裁决Agent | ✅ 代码已实现，文档有描述，但代码与文档不一致 | 1 |
| 叙事Agent | ✅ 代码已实现，文档有描述 | 0 |
| 世界叙事Agent | 🟡 仅 System Prompt 要素描述，无 API 参数 | 3 |
| 轻量AI评估 | 🔴 概念反复出现但从未定义 | 5 |

## 二、现状梳理

### 2.1 裁决Agent（ReasonerApiClient）

**代码实际配置**（`ReasonerApiClient.kt:44-55`）：

```
model: "deepseek-v4-pro"
reasoningEffort: "max"
responseFormat: json_object
maxTokens: 8192
stream: false
```

**代码内注释声称**（`ReasonerApiClient.kt:17-22`）：

```
model: deepseek-v4-pro
reasoningEffort: high（裁决需要高推理能力）
maxTokens: 1024（裁决结果较短）
stream: false
```

**两份描述之间的矛盾**：

| 参数 | 代码注释声称 | 代码实际使用 |
|------|------------|------------|
| reasoningEffort | `"high"` | `"max"` |
| maxTokens | `1024` | `8192` |

注释声称 `maxTokens=1024`（V2.1 早期版本可能只需 1024），但实际代码使用了 8192（V2.3 升级后 ActionResult 包含精确计量等额外字段，输出长度增长后调整了参数但注释未同步更新）。

### 2.2 叙事Agent（StorytellerApiClient）

代码实际配置：

```
model: "deepseek-v4-pro"
reasoningEffort: "medium"
responseFormat: json_object
maxTokens: 8192
stream: true
```

注释与代码一致，无矛盾。

### 2.3 世界叙事Agent

**V3.0 总纲 §6.3 定义**：

- System Prompt 核心要素已描述（角色定义、输出格式 JSON、风格指南、切换逻辑）
- 输入数据源已定义（时间跨度、WorldStateUpdate、autoPilotTick 报告）
- 独立的详细设计文档标注为"待编写"

**缺失的配置**：
- model 选择（pro vs flash？）
- reasoningEffort（加速摘要不需要极限推理，应该用 medium 还是 low？）
- maxTokens（摘要流每次输出 ≤150 字，约 200-300 tokens，但流式输出需要额外 buffer）
- stream（加速期间需要流式输出实现"持续更新"，应该为 true）
- temperature/其他参数
- 与叙事Agent 的切换逻辑在 API 层面如何实现（同一个 API key？session 复用？）

### 2.4 "轻量AI评估"

这是最大的缺口。"轻量AI评估"在《世界规则引擎》和《NPC自主行为系统》中出现了 **10+ 次**，但从未定义。

**出现位置汇总**：

| 文档 | 位置 | 触发场景 |
|------|------|----------|
| 世界规则引擎 | §4.2 | 势力/区域指标跨过危机阈值 |
| 世界规则引擎 | §3.2 | 势力解散后的区域归属判定 |
| 世界规则引擎 | §3.3 | 关键NPC被战斗死亡选中时 |
| NPC | §2.3 | 关键NPC好感度跨越边界 |
| NPC | §3.5 | 关键NPC生存状态突变 |
| NPC | §4.3 | NPC间罕见互动（关键NPC/生死/道德困境） |
| NPC | §4.4 | 外出超时（失踪判定） |
| NPC | §5.2 | 时间表重度异常解释 |
| NPC | §7.2 | (间接引用) |

**世界规则引擎 §4.2 的唯一参数描述**：

> "调用轻量AI：非独立Agent，一次对DeepSeek的标准调用（非流式，max_tokens=1024）"

仅此一句。没有 model、reasoningEffort、System Prompt、输入/输出格式之外的任何配置。

## 三、问题列表

---

### 🔴 问题1："轻量AI"作为反复出现的核心概念从未统一定义

**涉及文档**：世界规则引擎 §4.2、NPC 全文

**问题描述**：

"轻量AI评估/调用"在文档中出现了 10+ 次，但只有世界规则引擎 §4.2 给了一句话的参数描述。所有 NPC 系统中的"轻量AI评估"调用都没有定义：

- 调用哪个 model？(`deepseek-v4-pro` 还是 `deepseek-v4-flash`？后者更快更便宜，符合"轻量"的语义)
- reasoningEffort 多少？(轻量评估不需要深度推理，`low` 或 `medium` 即可)
- maxTokens 多少？(世界规则引擎写的是 1024，NPC 的关键NPC关系质变评估可能也需要 1024，但日常轻量调用可能只需要 512)
- 是否有独立的 System Prompt？还是复用裁决Agent的 System Prompt？(语义完全不同：裁决是判定行动成败，轻量评估是推断局势演变)
- 每个触发场景的输入结构是什么？(世界规则引擎 §4.2 定义了通用模板，但 NPC §3.5 的"好感度阶段跨越"和 NPC §4.3 的"罕见互动"需要的输入结构完全不同)

**后果**：开发时无法实现——不知道调用哪个 endpoint、传什么参数、发什么 prompt。

**修改建议**：新增独立文档《V3.0 Agent 配置规范》，或至少在某个文档中增加"AI 调用配置总表"小节。表结构：

```
| 调用点 | Model | reasoningEffort | maxTokens | Stream | System Prompt 来源 | 调用频率 |
```

---

### 🔴 问题2：世界叙事Agent 无 API 参数配置

**涉及文档**：V3.0 总纲 §6.3

**问题描述**：

世界叙事Agent 的职责、输入/输出格式、System Prompt 要素已定义，但所有 API 层参数缺失。与裁决Agent 和叙事Agent 不同，世界叙事Agent 没有对应的 `WorldStorytellerApiClient` 类设计，也没有在文档中指定 model/reasoningEffort/maxTokens/stream。

**修改建议**：在世界叙事Agent 独立设计文档中（或 V3.0 总纲 §6.3 中），增加 API 参数表：

```
| 参数 | 建议值 | 理由 |
|------|--------|------|
| model | deepseek-v4-flash | 摘要生成不需要深度叙事质量，flash 成本更低 |
| reasoningEffort | low | 摘要不需要推理，仅需基于输入的状态变更列表做文本转换 |
| maxTokens | 2048 | 每次摘要输出 ≤150 字(约200 tokens) + JSON 结构开销 |
| stream | true | 加速期间需要持续更新摘要流 |
| responseFormat | json_object | 输出为结构化 JSON |
```

---

### 🔴 问题3：裁决Agent 代码注释与代码实现不一致

**涉及文档**：`ReasonerApiClient.kt` 内注释 vs 实际代码

**问题描述**：

| 参数 | 注释声称 | 实际代码 |
|------|---------|---------|
| reasoningEffort | `"high"` | `"max"` |
| maxTokens | `1024` | `8192` |

V2.3 升级增加了 ActionResult 中的精确计量字段，输出长度增长，代码随之调整但注释未同步。同时，世界规则引擎 §4.2 引用的 `max_tokens=1024` 可能来源自此处的旧注释——如果开发者按文档给轻量AI设置 1024，但实际的裁决Agent 已经需要 8192，那"轻量"的 1024 token 预算可能不够。

**修改建议**：更新 `ReasonerApiClient.kt` 类注释，使参数表与实际代码一致。同时检查世界规则引擎 §4.2 的 `max_tokens=1024` 是否仍然合理。

---

### 🟡 问题4：轻量AI的 System Prompt 全部缺失

**涉及文档**：世界规则引擎 §4.2、NPC 全文

**问题描述**：

所有轻量AI调用点都没有定义 System Prompt。当前只有裁决Agent（`PromptBuilder.buildReasonerSystemPrompt()`）和叙事Agent 有独立的 System Prompt 生成逻辑。对比：

| 调用点 | System Prompt 来源 | 状态 |
|--------|-------------------|------|
| 裁决Agent | `PromptBuilder.buildReasonerSystemPrompt()` | ✅ 已实现 |
| 叙事Agent | `PromptBuilder.buildStorytellerSystemPrompt()` | ✅ 已实现 |
| 世界叙事Agent | V3.0 §6.3 仅要素描述 | 🟡 结构已定义，文本待编写 |
| 势力/区域质变评估 | **无** | ❌ |
| NPC 关系阶段跨越 | **无** | ❌ |
| NPC 生存状态突变 | **无** | ❌ |
| NPC 罕见互动 | **无** | ❌ |
| NPC 外出超时判定 | **无** | ❌ |

**修改建议**：轻量AI的所有调用点可以共用**一个**轻量评估 System Prompt（角色定义：你是末日世界局势的分析者，基于结构化数据推断局势演变），只需变化 user message 的输入结构。建议新增 `PromptBuilder.buildLightweightEvalSystemPrompt()` 方法。各个调用点只需要构建不同的 user message 即可。

### 🟡 问题5：世界规则引擎 AI评估 Prompt 输出结构遗漏 `npcCasualtyDecision`

**涉及文档**：世界规则引擎 §4.2

**问题描述**：

§4.2 定义的 AI 评估输出结构中，`stateChanges` 数组的 `target` 和 `attribute` 字段只能描述势力/区域级别的变更。但 §3.3 规定："关键NPC：死亡判定前触发轻量AI评估（允许叙事保护但非绝对豁免）"——这一评估结果需要通过 AI 输出 `npcCasualtyDecision` 字段来传达（是否豁免该关键NPC的死亡），但当前的 AI 输出结构中完全没有这个字段。

**修改建议**：在 §4.2 的 AI 评估输出结构中增加可选字段：

```
"npcCasualtyDecision": {
  "npcId": "...",
  "decision": "kill" | "spare" | "severe_injury",
  "rationale": "叙事理由（如'他在关键时刻被同伴拖走'或'命运没有眷顾他'）"
}
```

仅在触发条件为"关键NPC被战斗死亡选中"时填充此字段。

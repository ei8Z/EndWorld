### 🔴 问题1：记忆队列扩容后三处数值引用未同步更新

**涉及文档**：《NPC》§2.1 / §3.4 / §9.1

**矛盾描述**：

NPC 文档经历了一次手动修订——记忆队列容量从 3/5 扩展为 6/10（§3.4 表格：接触NPC 6条，关键NPC 10条）。但以下三处仍引用旧数值：

| 位置 | 旧数值 | 新数值 | 说明 |
|------|--------|--------|------|
| §2.1 第三层关键NPC描述 | "详细记忆队列扩展为5条" | 应为10条 | 概念描述与数据表不一致 |
| §3.4 远景记忆保护压缩频率 | "接触NPC每12条新记忆才压缩1条，关键NPC每15条才压缩1条" | 接触NPC应改为24条(6×4)，关键NPC应改为30条(10×3) | 远景保护的压缩频率是基于"队列容量×倍数"计算的，容量变了但倍数未更新 |
| §9.1 MVP 实现范围 | "记忆队列（3条详细记忆）" | 应为"记忆队列（6条详细记忆）" | MVP范围引用旧值，开发时会按6条实现但文档要求3条 |

**影响**：开发时按 §3.4 表格实现 6/10 条，但 §2.1 的概念描述和 §9.1 的 MVP 范围都是旧数值。若只看 §9.1 做 MVP 会产生歧义。

**修改建议**：
- §2.1：将"详细记忆队列扩展为5条"改为"详细记忆队列扩展为10条"
- §3.4 远景保护：将"接触NPC每12条新记忆才压缩1条"改为"接触NPC每24条新记忆才压缩1条"，将"关键NPC每15条才压缩1条"改为"关键NPC每30条才压缩1条"。在修改处增加注释说明计算公式：`压缩间隔 = 队列容量 × 4（接触NPC）/ × 3（关键NPC）`
- §9.1：将"记忆队列（3条详细记忆）"改为"记忆队列（6条详细记忆）"

### 🔴 问题2："伤病率"是一个无人维护的派生变量

**涉及文档**：《世界规则引擎》§3.1

**矛盾描述**：

§3.1 人力修正公式：

> 人力修正 = max(0.1, 1.0 - 武装率 - 伤病率)
> 伤病率 = 受伤人口/总人口

**数据源缺失**：世界规则引擎不管理 NPC 个体伤病状态（§1："不模拟单个NPC行为"）。NPC 行为系统管理每个接触 NPC 的"受伤"状态标签（§3.1），但：
- 接触 NPC 仅 10-30 个，不构成"总人口"
- 背景 NPC（数百个）没有个体"受伤"状态——只有群体标签
- 没有任何模块负责将个体伤病汇总为宏观"伤病率"

这是一个**公式引用了不存在的数据源**的典型问题。"伤病率"在公式中使用，但没有任何每日结算步骤负责计算它。

**数值后果**：如果伤病率恒为 0（未计算），人力修正 = max(0.1, 1.0 - 0.6 - 0) = 0.4。但如果实际上有大量伤员，真实人力修正应该是 max(0.1, 1.0 - 0.6 - 0.2) = 0.3。差距 25% 的资源生产效率偏差。

**修改建议**：
- 方案A（推荐）：将伤病率从自动推导改为手动维护——在势力状态标签中增加"伤病率估算"字段（如"轻微伤亡/中等伤亡/严重伤亡"→对应伤病率 0.05/0.15/0.30），由世界规则引擎在每日结算 Step 2 状态检查时根据 CasualtyReport 累计伤亡数据和需求过载致死记录更新
- 方案B：在 NPC 行为系统中增加"伤病率汇总"接口——每日结算时遍历所有接触 NPC 统计"受伤"标签数量，按接触NPC占势力人口比例反推宏观伤病率。缺点是 10-30 个样本反推数百人可能有统计偏差
- 无论选择哪个方案，必须在世界规则引擎 §3.1 或 §5 中明确伤病率的计算来源和更新频率

### 🔴 问题3：医疗/水/弹药的宏观消耗公式缺失

**涉及文档**：《世界规则引擎》§3.1

**矛盾描述**：

§3.1 只给出了**食物**的完整更新公式：

```
食物储备 = 食物储备 + 食物生产 - 食物消耗 - 食物损耗
食物消耗 = 人口 × 人均日消耗
```

第七轮修订在医疗换算表中注明"日常防疫消费计入宏观公式中的人口 × 人均日消耗"。但：
- 医疗物资的**消耗公式**在哪里？是 `医疗消耗 = 人口 × 人均日医疗消耗` 吗？"人均日医疗消耗"是否等于 1 单位/人日？
- 水资源的消耗公式是什么？`水消耗 = 人口 × 人均日水消耗`？"人均日水消耗"是否等于 1 人口天 = 3000ml？
- 弹药的消耗公式是什么？弹药只有在战斗时才消耗吗？还是日常有维护损耗？

文档用"类似逻辑"一笔带过，但每个资源池的消耗逻辑并不相同：
- 食物：日常消耗（人口×固定值）
- 水：日常消耗（人口×固定值）+ 天气修正（炎热天气消耗更多）
- 医疗：日常防疫（人口×固定值）+ 伤病治疗额外扣费（按实际治疗次数）
- 弹药：仅在战斗结算时消耗（非日常消耗）

**修改建议**：在 §3.1 中为每种资源池补全消耗公式：

```
食物消耗 = 人口 × 人均日食物消耗（1人口天）
水消耗 = 人口 × 人均日水消耗（1人口天） × 天气修正（炎热×1.3，正常×1.0，寒冷×0.8）
日常医疗防疫消耗 = 人口 × 人均日医疗消耗（1单位，即0.05个标准医疗包）
  + 额外伤病治疗消耗（每次20单位，由NPC系统每日结算时反馈治疗次数）
弹药消耗 = 仅在战斗结算时产生（兰彻斯特公式输出弹药消耗率，每场战斗消耗弹药储备 × 消耗率）
```

### 🔴 问题4：加速模式医疗消耗未引用第七轮修订的20单位成本

**涉及文档**：《V3.0》§3.3 vs 《世界规则引擎》§3.1 vs 《NPC》§3.3

**矛盾描述**：

V3.0 §3.3 加速模式自动导航规则：

> "若受伤且有医疗物资（优先使用势力医疗物资，其次为背包医疗物资）→自动使用"

第七轮修订将势力治疗成本从 1 单位改为 20 单位（≈1 个标准医疗包）。但 §3.3 的自动导航规则没有引用这个新成本：
- 优先使用势力医疗物资时，是每次自动治疗消耗 20 单位吗？
- 如果势力医疗物资只有 15 单位（不足以支付一次治疗），是否回退到使用玩家背包的医疗包？
- 如果玩家背包也没有完整医疗包，是否跳过治疗（保持受伤状态）？

**数值后果**：如果加速模式的自动治疗沿用了旧逻辑（1 单位/次），玩家在营地加速休养期间受伤 NPC 的自动治疗几乎是免费的——第七轮修复的意义被架空。

**修改建议**：将 §3.3 的医疗行改为：

```
- 若受伤且有医疗物资 → 自动使用：
  - 优先使用势力医疗物资（每次消耗 20 单位，≈1 个标准医疗包，见世界规则引擎§3.1 伤病治疗行）
  - 势力医疗物资不足 20 单位时，回退使用玩家背包中的完整医疗包
  - 若两者均不足 → 保持受伤状态，等待玩家手动获取医疗物资
  - 自动治疗的消耗记录在加速结束摘要中体现
```

### 🟡 问题5：冲突概率公式产生"强者恒强"正反馈无平衡机制

**涉及文档**：《世界规则引擎》§3.3

**矛盾描述**：

冲突概率公式中：

```
兵力比因子 = min(己方兵力/敌方兵力, 2.0)
```

这是一个**非对称双向计算**——势力A的攻击意愿由 A/B 决定，势力B的攻击意愿由 B/A 决定。

**正反馈循环推演**：
- 初始：A 兵力 100，B 兵力 50。A 攻击概率因子 = 2.0，B 攻击概率因子 = 0.5
- A 更愿意攻击（2x概率）+ B 更不敢反击（0.5x概率）→ A 大概率获胜后兵力差距进一步拉大
- 下一轮：A 兵力 80，B 兵力 20。A 因子 = 2.0（cap），B 因子 = 0.25
- 循环结果是强者恒强——第一场战斗的胜者会连续获胜直到吞并所有弱者

文档中没有"弱势方拼死一搏"（如兵力比 < 0.3 时因子反转）或"第三方介入"（同盟势力协防）的平衡机制。整个战斗系统的稳态是单极霸权——与"末日世界的多方势力动态平衡"的设计目标矛盾。

**修改建议**：在冲突概率公式后增加平衡机制：

```
弱势方修正：若己方兵力/敌方兵力 < 0.3，兵力比因子取反转为 2.0（弱势方在绝境中拼死一搏）
第三方介入：若交战双方兵力差距 > 3:1，相邻的第三方势力（关系为"同盟"或"中立偏友好"）有 30% 概率介入协防弱势方
```

或者在冲突概率公式下方增加注释承认这是有意设计（"强者吞并弱者是末日世界的自然规律"），并说明平衡由 AI 评估阈值触发来提供（"势力濒临覆灭时触发AI评估，AI可能生成新的同盟或外部干涉"）。

开发者建议：这个情况比较复杂，弱势方如果忠诚度高，那么可能有拼死一搏，绝境反击，但忠诚度低那就可能是直接溃败，强势方无伤得到胜利。第三方介入的前提是：为同盟参，或有唇亡齿寒的责任感，或有具体的协防条约；参加战斗能获得高额的报酬，破坏强势方一家独大的趋势；总之第三方介入需要满足条件。

### 🟡 问题6：NPC死亡双路径在同一结算中的优先级冲突

**涉及文档**：《NPC》§4.4 vs §7.1

**矛盾描述**：

NPC 死亡有四条路径，可能在同一日结算中同时触发：
- **需求过载致死**（§4.4）：连续3天饥饿/口渴触顶
- **伤病恶化致死**（§4.4）：医疗需求连续3日触顶
- **战斗伤亡**（§7.1 CasualtyReport）：世界规则引擎推送
- **环境致死**（§4.4）：所在场景遭遇灾难

推演：NPC 老张在第8日午夜结算时——食物需求连续3天触顶（触发饥饿致死），同时收到 CasualtyReport 标记他在昨日战斗中被流弹击中（战斗伤亡）。两个死亡路径同时触发，谁的死亡原因写入环境记忆？谁的通知发给叙事Agent？

**后果**：如果同时写入两条环境记忆（"Day 8 因饥饿死亡"+"Day 8 在战斗中阵亡"），叙事 Agent 面对矛盾信息。如果只写一条，优先级规则缺失导致实现不一致。

**修改建议**：在 NPC §4.4 末尾增加死亡路径优先级：

```
多条死亡路径同时触发时的优先级：
1. CasualtyReport 战斗死亡（叙事价值最高——有明确的因果关系和戏剧性）
2. 环境致死（灾难、尸潮——外部事件驱动，叙事价值次高）
3. 伤病恶化致死（医疗需求过载——渐进式悲剧，叙事价值中）
4. 需求过载致死（饥饿/口渴——慢性死亡，叙事价值最低但反映资源危机）

当高优先级路径触发时，低优先级路径的死亡判定自动取消（NPC 不会同时死于两个原因）。
只有最高优先级的原因被写入环境记忆和 CasualtyReport。
```

### 🟡 问题7：预演轻量需求追赶的数值公式细节在重构中丢失

**涉及文档**：《NPC》§4.3

**矛盾描述**：

第七轮重构将跨Region结算从"即时结算"改为"分阶段异步预演"。旧版有一个独立段落详细描述轻量需求追赶的公式：

> "按'当前GameClock时间 - 上次每日结算时间'的差值，按比例推进需求值（如已过15小时则推进 15/24 的日增量）"

新版将这句压缩为嵌入在预演规则 bullet point 中的半句话：

> "预演前对参与NPC执行轻量需求追赶（按'当前GameClock时间 - 上次每日结算时间'的差值，按比例推进需求值）"

丢失的精确信息：比例因子是 `时间差 / 24小时`（隐含在旧版的"15/24"示例中）。实现时可能使用不同的小时数分母（如用 GameClock 的总分钟数除以 1440）。

**修改建议**：在 NPC §4.3 预演规则中恢复公式精度：

```
预演前对参与NPC执行轻量需求追赶：
追赶比例 = (当前GameClock总分钟数 - 上次每日结算时的总分钟数) / 1440
追赶后的需求值 = 当前存储需求值 + 日增量 × 追赶比例
此追赶仅用于本次互动判定，不写入持久存储（正式写入仍等午夜每日结算）。
若追赶比例 < 1/24（不足1游戏小时），跳过追赶。
```

### 🟡 问题8：事件概率模型被保底机制架空

**涉及文档**：《世界规则引擎》§2.3

**矛盾描述**：

§2.3 定义了两套事件生成规则：

| 规则 | 数值 |
|------|------|
| 概率生成 | 基础生成概率 = 0.03/势力/日 |
| 保底强制 | 全局每日至少 minEventsPerDay 个（丧尸末日=1，核战凛冬=0） |

**数值推演**（丧尸末日，10 个势力）：
- 期望事件数 = 0.03 × 10 = **0.3 个/日**
- 实际保底 = **1 个/日**
- 保底触发率 = 实际/期望 = **333%**

概率生成几乎是装饰性的——在绝大多数日子里，系统不是因为"概率抽中了"而产生事件，而是因为"保底要求每天至少1个"而强制生成。开发时可以直接忽略概率模型，每天都硬编码生成 1 个事件，结果几乎相同。

这不是 bug（保底本身是合理设计），但文档将概率描述为主要机制、保底为辅助约束——实际运行中是反过来的。

**修改建议**：在 §2.3 中增加一句坦白说明：

```
在势力数量较少（<30个）的典型配置中，实际事件生成主要由 minEventsPerDay 保底机制驱动，
概率模型在势力数量增长后逐渐成为主导。这不是设计缺陷——保底机制确保小规模世界仍然有
足够的事件密度以维持末日氛围。
```

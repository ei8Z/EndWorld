## 问题列表

### 🟢 问题1：NPC §3.3 "需求过载致死"的"独立运行"声明已过时

**涉及文档**：《NPC》§3.3

**问题描述**：

NPC §3.3 第 251 行：

> "此判定与世界规则引擎的宏观人口扣减独立运行——宏观扣减的是背景NPC，需求过载致死的是接触NPC个体。"

Q1 修订在 §4.4 新增了 `PopulationChangeNotification`，使非战斗死亡（含需求过载致死）会立即通知世界规则引擎更新势力人口。§3.3 的"独立运行"声明已与 §4.4 的实际行为矛盾。

**修改建议**：删除"此判定与世界规则引擎的宏观人口扣减独立运行——宏观扣减的是背景NPC，需求过载致死的是接触NPC个体"，改为：

```
触发死亡判定的同时，NPC行为系统立即向世界规则引擎发送 PopulationChangeNotification（见§4.4），同步更新势力人口统计。
```

---

### 🟢 问题2：NPC §4.4 "死亡判定与CasualtyReport的关系"描述死亡路径为"两条"

**涉及文档**：《NPC》§4.4

**问题描述**：

NPC §4.4 第 499 行：

> "NPC死亡有两条路径，互不替代"

第七轮审查新增了"死亡路径优先级"表，定义了四条独立路径（战斗/环境/伤病恶化/需求过载）。§4.4 的"两条路径"描述已落后于实际设计。

**修改建议**：将第 498-502 行简化为引用上方的优先级表，避免重复描述：

```
**死亡判定与CasualtyReport的关系**：
NPC死亡有四条独立路径（详见上方"死亡路径优先级"表），它们可能在同一结算中同时触发——优先级表定义了裁决规则。
例如：NPC在战斗中断腿→CasualtyReport标记为newInjury→伤情在后续结算中恶化为死亡（此时路径3"伤病恶化"覆盖路径1"战斗死亡"的新伤标记，而非同时触发两条死亡判定）。
```

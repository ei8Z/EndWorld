### 🟡 问题1：加速模式中"持续生成摘要"与批量追赶的数据源矛盾

**涉及文档**：《V3.0》§3.3

**问题描述**：

§3.3 加速模式步骤 4-5-8 之间存在时序张力：

> 步骤4：世界规则引擎标记为追赶模式——**加速结束时一次性批量追赶**
> 步骤5：世界叙事Agent**持续生成**时间流摘要
> 步骤8：NPC行为系统以批量追赶模式运行——**加速结束时一次性推进**

如果世界规则引擎和NPC行为系统的状态变更都在加速结束时一次性计算，那么步骤5中世界叙事Agent在加速**期间**"持续生成"摘要时，使用的是**什么数据**？

两种可能解释及其问题：
- **解释A**（摘要基于加速开始前的旧状态）：如果加速跨越多天，世界叙事Agent持续输出"暂无变化"的摘要，违背了"让玩家感知世界变化"的设计目标
- **解释B**（摘要基于阶段性估算）：需要在加速期间对未结算的状态做增量估算，但这与"批量追赶"策略（放弃中间态）的原则矛盾

文档未定义加速期间的摘要数据来源。

**修改建议**：将步骤5改为分阶段描述：

```
5. 世界叙事Agent生成时间流摘要：
   - 加速期间：按固定现实时间间隔（如每3秒）生成阶段性摘要，内容基于加速开始时状态的逻辑推演（世界规则引擎提供"预期变化"而非结算结果）
   - 加速结束时：基于批量追赶结算的实际结果，生成最终摘要并标记 final: true
```

### 🟡 问题2：NPC医疗死亡判定的"双轨"脱节——受伤条件与医疗需求数值不关联

**涉及文档**：《NPC》§3.3 vs §4.4

**问题描述**：

NPC死亡在 §4.4 中有一条独立的路径：

> "NPC受伤且未获得医疗"

这是一个**状态标签驱动**的条件——检查"受伤"标签是否存在+"是否获得过医疗"。

但同时 §3.3 维护了一个**数值驱动**的医疗需求系统——医疗紧迫度（0-100），受伤时日增量+360。

这两个系统独立运行，但语义上重叠：

| 维度 | §4.4 死亡判定 | §3.3 医疗需求系统 |
|------|-------------|-----------------|
| 触发方式 | 状态标签检查（"受伤"=true） | 紧迫度值累积（+360/日） |
| 治疗记录 | "是否获得过医疗"（binary） | 治疗将紧迫度归零 |
| 死亡时机 | 未定义时间门槛（"未获得医疗"无天数限定） | 紧迫度达到100后持续增长但无直接后果 |

问题：§4.4 说"受伤且未获得医疗→死亡"，但没有指定**未治疗多久**会死亡。而 §3.3 维护了一个精确的医疗需求数值（0-100），这个数值在 §4.4 的死亡判定中完全未被引用。

**修改建议**：将 §4.4 的死亡条件改为引用 §3.3 的数值：

```
| 死亡 | ...或NPC保持"受伤"状态标签且医疗需求连续3个每日结算处于100（未获得治疗），触发死亡判定 |
```

并在 §3.3 的医疗需求满足后增加：

```
若NPC的医疗需求连续3个每日结算均处于100（饱和），在第3次结算时触发死亡判定——NPC因伤病恶化且缺乏治疗而死亡。
```

### 🟡 问题3：势力自动分配医疗的触发时机未定义

**涉及文档**：《NPC》§3.3

**问题描述**：

第五轮修订在 §3.3 增加了"所在势力自动分配"的治疗来源。但触发时机未定义：

> "仅在该势力医疗物资 > 0 时触发，消耗 1 单位势力医疗物资...可消除 1 个 NPC 的医疗需求"

"触发"发生在什么时候？

- **方案A（即时触发）**：NPC受伤后立即检查势力医疗物资并自动治疗——与"每日结算"节奏不一致
- **方案B（每日结算触发）**：在每日结算时，统一检查所有受伤NPC并按优先级分配医疗物资——NPC可能在受伤后等待长达24小时才获得治疗

两种方案各有后果：
- 方案A：即时性合理（受伤→立即送医），但打破了每日批量结算的节奏
- 方案B：与每日结算节奏一致，但NPC从中午受伤到午夜才被治疗，期间医疗需求已增长+180

**修改建议**：在 §3.3 中明确触发时机：

```
势力自动分配的治疗在每日结算时统一执行，与NPC需求更新同步：
1. 收集所有状态标签为"受伤"的该势力接触NPC
2. 按分诊优先级排序（领袖 > 战斗人员 > 非战斗人员）
3. 依次消耗势力医疗物资进行治疗，直至医疗物资耗尽或无更多受伤NPC
4. 未被治疗的NPC保持受伤状态，等待次日结算或玩家治疗
```

### 🟡 问题4：加速模式玩家自动导航中医疗物资来源未指定

**涉及文档**：《V3.0》§3.3

**问题描述**：

§3.3 自动导航规则对食物和水的来源做了明确分支：

> "若（势力资源或背包）有食物且饱食度低于阈值→自动进食"
> "若（势力资源或背包）有水且口渴度低于阈值→自动饮水"

但对医疗物资只说：

> "若受伤且有医疗物资→自动使用"

没有指定"医疗物资"来自玩家背包还是势力资源池。食物和水有明确的环境资源优先逻辑，但医疗在这套逻辑中被遗漏了。

**修改建议**：将医疗物资行改为：

```
- 若受伤且有医疗物资（优先使用势力医疗物资，其次为背包医疗物资）→自动使用
```

### 🟢 问题5：NPC行为优先级在每日结算粒度下的叙事断层

**涉及文档**：《NPC》§3.2 vs §4.1

**问题描述**：

§4.1 行为优先级定义：

> "1. 生存需求（饥饿/口渴/受伤）→ 覆盖时间表，优先满足"

§3.2 位置来源的两种机制：

> "行为决策覆盖——每日结算时判定"

在每日结算粒度下，NPC的需求在午夜一次性推进24小时量→行为决策也在午夜一次性判定。这意味着：

**推演**：NPC老王在Day N的午夜结算时，食物需求从30跳到100（触顶）。行为决策："饥饿→需要进食"。覆盖时间表，老王从现在起前往食堂。但此刻是**午夜**——老王在深夜0点起床去食堂？食堂可能按时间表应该在早上8点才有人。

这个张力源于：每日结算将所有行为决策集中在午夜，但时间表驱动的合理行为（如进食）有时间段限制。

每天午夜，所有触顶饥饿的NPC都会在午夜0点"集体冲向食堂"——行为合理但叙事荒谬。

**修改建议**：在 §4.1 行为优先级后增加：

```
行为决策的时间表兼容规则：
- 行为决策在每日结算时判定，但决策的"执行"可能延迟到下一个合适的时间段
- 若决策行为（如进食）对应的目标位置在当前时间段不可用（如深夜食堂关闭），
  行为标记为"排队等待"，在目标位置的第一个可用时间段执行
- 紧急生存需求（生命威胁级）无视时间段限制
```

### 🟢 问题6：世界规则引擎医疗物资的单位存在"人口天"与"可治疗人次"双重语义

**涉及文档**：《世界规则引擎》§2.2 vs §3.1

**问题描述**：

§2.2 势力资源池定义医疗物资单位为"可治疗人次"。

§3.1 标准单位换算表中医疗物资行定义为"1人次的日常医疗保障 ≈ 0.05 个标准医疗包"，并注"1个标准医疗包 = 20人口天的医疗物资"。

这里出现了三个单位在同一换算链中：
- **治疗人次**（§2.2资源池单位）
- **人口天**（§3.1换算表引用）
- **标准医疗包**（玩家物品单位）

"人口天"的医疗物资和"可治疗人次"是否完全等价？一个人口天的医疗保障（预防、日常用药）与一次治疗（处理伤口、手术）是不同的概念。将两者等价（1人口天=1治疗人次）简化了设计但降低了模型精度。

当前文档暗示：1人口天医疗物资 = 1可治疗人次。这在数值上可行但在语义上有微妙差异——日常保障不等于一次治疗。

**修改建议**：在 §2.2 医疗物资行增加注释：

```
医疗物资 | 浮点数 | 单位：可治疗人次（1人次 ≈ 1人口天的医疗资源消耗量，含预防+治疗；与§3.1换算表对齐）
```

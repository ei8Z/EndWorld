# 末日求生 · AI叙事游戏 开发文档 V3.0

> **版本**：V3.0 动态世界模拟
> **基于**：V2.2 双Agent架构 + V2.3 物品精确计量
> **核心升级**：从“静态叙事引擎”升级为“动态世界模拟器”
> **设计哲学**：一个持续运行的世界，玩家在其中互动，AI将世界状态转化为沉浸式叙事


## 一、V3.0的核心突破

### 1.1 V2的成就与局限

V2构建了一个可靠的叙事管道：玩家行动→裁决Agent→叙事Agent→等待下一个行动。这个管道在单次交互层面表现优秀，但存在一个根本性假设：**世界在玩家不行动时是静止的。**

V3.0打破这个假设。模拟层（世界规则引擎+NPC自主行为系统）持续运转，无论玩家是否行动。玩家不是在“推动剧情”，而是在一个动态世界中做出选择——世界会因这些选择而改变，但不会因玩家犹豫而等待。

### 1.2 V3.0的设计目标

1. **世界持续运转**：势力消长、事件传播、NPC生活独立于玩家行动
2. **时间真实流动**：玩家对时间有完全掌控权（加速/减速/暂停），但时间一旦流动就不受玩家意志影响
3. **选择有分量**：加速意味着错过，犹豫意味着停滞，每一个时间决策都有后果
4. **死亡不是终点**：角色死亡后世界继续，玩家可以继承世界状态开始新故事

## 三、异步时间模型

### 3.1 核心概念：时间膨胀

V3.0采用异步时间模型。游戏世界时间和玩家决策时间是两个独立的维度：

- **时间线A（游戏世界时间）**：世界规则引擎和NPC行为系统的运行基准
- **时间线B（玩家决策时间）**：玩家阅读叙事、思考选项、输入行动的现实时间

两者通过**时间膨胀**机制关联：玩家思考时世界暂停，玩家做出消耗时间的行动后世界解冻并推进。

### 3.2 三速控制

玩家可以在三个速度档位之间自由切换。速度切换属于**元行动**——不消耗游戏内时间，不经过裁决Agent。

| 档位 | 时间比例 | 适用场景 | suggestions |
|------|----------|----------|-------------|
| **减速（子弹时间）** | 现实1秒 = 游戏内3秒 | 战斗、紧急医疗、危机决策 | 秒级/分钟级选项 |
| **正常** | 世界仅在玩家行动消耗的时间中推进，其余时间暂停 | 探索、社交、搜索 | 30分钟-数小时选项 |
| **加速** | 现实1秒 = 游戏内15分钟 | 移动、等待、休息、制作 | **无suggestions**，替换为时间流摘要面板 |

**场景自适应**：系统根据当前场景类型建议速度档位，但玩家始终可手动覆盖。

### 3.3 加速模式

当玩家选择“加速”元行动时：

1. 当前的具体行动选项**折叠作废**（世界状态即将变化，旧选项不再适用）
2. 世界时钟开始快速推进
3. 玩家角色进入**自动导航模式**：按预设生存本能行动（优先消耗当前所在地的友好势力资源，其次为背包物资），不进行策略性选择
4. 世界规则引擎标记为追赶模式——不逐日连续结算，而是在加速结束时一次性批量追赶整个时间段的模拟效果（含跨午夜时的每日结算补执行）
5. 世界叙事Agent采用**双模架构**解决 AI 延迟问题（详见《Agent 配置规范》§4）：
   - **加速期间（本地模式）**：使用客户端预设模板引擎（纯 Java/Kotlin 字符串格式化，<1ms 延迟），根据世界规则引擎提供的"预期变化"数据（势力资源消耗趋势、事件传播概率、NPC 状态预测），按预设模板生成简短的状态栏文本。此阶段不调用任何 AI 模型
   - **加速结束时（云端模式）**：调用一次世界叙事Agent（DeepSeek Pro, reasoningEffort=medium, maxTokens=4096），输入整个加速期间的所有累积变更和本地模式生成的模板文本序列，生成高质量的最终摘要并标记 `final: true`
   - > 未来扩展（V3.1+）：若 MemOS `memos-extractor-0.6b` 提供结构化数据→自然语言摘要的专门接口，可用于替代本地模板引擎，提升本地阶段文本的多样性和自然度。当前版本使用纯模板以保证零延迟和零成本
6. UI从suggestions面板切换为**时间流摘要面板**
7. 玩家随时可发出”恢复正常速度”元行动
8. NPC行为系统在加速期间以批量追赶模式运行——不逐小时结算，加速结束时一次性推进NPC的时间表、需求和互动。世界叙事Agent的摘要流中包含显著NPC行为（死亡、离开、关系阶段跨越）

**加速期间的角色自动导航规则**：

资源消耗优先级（先判断环境资源，再使用个人物资）：
1. 若当前Location属于友好/同盟势力（势力关系矩阵中标记为同盟或中立偏友好），且该势力的食物/水资源池 > 0：
   - 自动导航优先消耗势力资源池（同步扣除模拟层对应的人口天数，换算标准见世界规则引擎§3.1）
   - 仅在势力资源耗尽后才消耗玩家背包
2. 若当前Location无友好势力或势力资源耗尽：
   - 使用玩家背包物资

具体生存行为：
- 若（势力资源或背包）有食物且饱食度低于阈值→自动进食
- 若（势力资源或背包）有水且口渴度低于阈值→自动饮水
- 若遭遇致命威胁→尝试逃跑
- 若受伤且有医疗物资 → 自动使用：
  - 优先使用势力医疗物资（每次消耗 20 单位，≈1 个标准医疗包，见世界规则引擎§3.1 伤病治疗行）
  - 势力医疗物资不足 20 单位时，回退使用玩家背包中的完整医疗包
  - 若两者均不足 → 保持受伤状态，等待玩家手动获取医疗物资
- 若无以上需求→停留在安全位置
- **若无法满足生存需求（无食物、无水、无法逃跑）→角色可能死亡**
- 消耗势力资源时，记录消耗量并在加速结束摘要中体现（如"在红松营地休养3天，消耗了营地少量食物和水"）

**加速停止时**：
- 世界时钟暂停
- 系统展示当前场景新状态（基于加速期间模拟层运行结果）
- 叙事Agent基于新状态生成场景描述和新的行动选项
- 玩家重新面对选择

### 3.4 减速模式

当玩家选择“减速”元行动时：

- 世界时间流速降低
- 叙事Agent的叙事密度增加（更多感官细节、更细腻的动作描写）
- suggestions展示超短时间跨度选项（秒级/分钟级）

示例选项：“侧身闪避”、“反击头部”、“呼叫支援”、“使用医疗包止血”

### 3.5 模拟层运行节奏

模拟层的运行直接挂钩游戏内时钟，不依赖玩家行动。

采用**每日批量结算**策略（与NPC系统文档对齐）：NPC需求值不再逐小时递增，而是在每日结算时一次性推进24小时的需求量，行为决策在同一结算点统一判定，消除"需求触发"与"行为响应"之间的时间差。

- **游戏内每经过1天（午夜跨过）**：
  - 世界规则引擎每日结算（资源更新→状态检查→冲突判定→战斗结算→事件传播→阈值检测与AI评估）
  - NPC行为系统完整结算（一次性推进24小时需求值→基于紧迫度排序的行为决策→NPC间互动→离开判定→时间表更新）
- **玩家跨Region移动时**：采用分阶段异步预演机制，避免边界跨越的毫秒内全量同步结算：
  - 当玩家距目标Region边界<1个Location时（或导航目标明确为某Region时），系统在后台分批异步预演目标Region的NPC互动（每批≤5对，批次间隔≥100ms，总超时3秒）
  - 预演结果暂存于临时缓冲区，不写入持久存储
  - 玩家实际跨越边界时：先应用缓冲区中的预演结果（写入持久存储），再组装裁决Agent的 RulingContext（此时 nearbyNpcs 为预演后的最新状态），最后调用裁决Agent判定移动行动。此顺序确保裁决Agent看到的是目标Region的当前状态
  - 若玩家取消移动（未实际跨越边界）：丢弃缓冲区，不产生任何持久影响
  - 预演仅判定非致死互动——死亡、离开、关系破裂等重大结果推迟到下一次每日结算。需求追赶值不写入持久存储（正式写入等午夜每日结算）
  - 详见NPC文档§4.3
- **玩家行动即时触发**：裁决Agent判定后，直接影响立即生效于模拟层数据
- **加速模式特殊处理**：采用批量追赶模式——加速结束时一次性计算整个时间段的模拟效果（包含跨午夜时的每日结算补执行）。详见§3.3
- **生存状态机被动消耗**：不跟随每日结算——在正常/减速模式下跟随每次玩家行动推进（按该行动消耗的实际时间），在加速模式下通过 `advanceWorldTime()` 按跳跃的时间段推进（与V2.x逻辑一致）


## 四、三层事件体系

| 事件层级 | 管理模块 | 范围 | 触发方式 | 示例 |
|----------|----------|------|----------|------|
| **全局事件** | 世界规则引擎 | 跨区域传播，影响势力/区域/人口 | 每日结算时自动产生或AI评估产生 | 尸潮、难民潮、疫病、势力覆灭 |
| **区域事件** | 世界规则引擎（产生）+ NPC行为系统（响应）+ 生存状态机（环境类） | 影响单个区域内的NPC和场景 | 全局事件传播到区域、玩家行动后果、环境变化 | 哨卡被袭击、物资点被发现、天气骤变 |
| **遭遇事件** | EventDeck（V2保留） | 影响玩家当前行动 | 裁决Agent在行动判定时触发 | 搜索时遇到丧尸、交涉时对方突然翻脸 |

**层级关系**：上层事件产生下层事件。全局事件传播到区域时产生区域事件，区域事件为遭遇事件提供触发条件。


## 五、玩家行动的两条影响路径

### 5.1 直接影响（立即生效）

通过裁决Agent→ActionResult，分两路影响：
- → 生存状态机：玩家自身状态（HP、SP、饱食度、物资背包）
- → 模拟层数据：当前场景状态（如炸毁军火库→该区域物资-30%）

两条路径均立即生效。

### 5.2 连锁反应（按模拟层节奏生效）

由直接影响引发的次级效应，在模拟层结算时判定：
- 军火库被毁→该势力武装程度下降→下次每日结算时，敌对势力可能趁机进攻
- NPC被救→好感度变化→下次NPC行为系统结算时，该NPC可能主动提供帮助

**设计原则**：直接影响让玩家感受到“我改变了世界”，连锁反应让玩家感受到“世界因我的行为而演变”。


## 六、叙事层Agent职责定义

### 6.1 裁决Agent

**调用时机**：仅在正常速度和减速模式下调用。加速模式下不调用。

**输入**：见 §6.1.1 RulingContext 数据结构

**输出**：结构化ActionResult（成败、消耗、伤病、事件触发、叙事摘要）

**职责边界**：裁决Agent是”模拟层数据的执行者”，而非”独立判官”。它基于模拟层提供的精确条件进行判定。

**玩家感知延迟**：裁决Agent（Pro/max/非流式，约 8-20 秒）+ 叙事Agent（Pro/medium/流式，首token 2-5 秒 + 文本流 3-8 秒）= 每次行动累计等待 10-25 秒。此为云端 AI 的物理延迟上限，非设计缺陷。UI 在等待期间展示”判定中...”→”叙事生成中...”两步加载状态。减速模式（子弹时间）下延迟不变——玩家获得更细腻的叙事密度，但每次行动的 AI 等待时间相同。未来优化方向（V3.1+）：裁决Agent 改为流式输出，提前暴露判定结果使叙事Agent 可并行预启动。

#### 6.1.1 RulingContext 数据结构

为消除三份文档对”裁决Agent收到什么”描述不一致的问题，定义统一的 `RulingContext` 输入结构：

| 字段 | 来源模块 | 说明 |
|------|----------|------|
| `playerAction` | ActionParsed | 玩家行动的解析结构（类型、目标、方式、风险等级） |
| `worldSnapshot` | 生存状态机 | HP/SP/饱食度/口渴度/疲劳度/物资背包/装备/伤病 |
| `zoneState` | 世界规则引擎 | 玩家所在区域的威胁等级、控制势力、状态标签 |
| `controllingFaction` | 世界规则引擎 | 控制势力的名称、资源概况、当前目标 |
| `nearbyNpcs` | NPC行为系统 | 附近NPC列表，每人含姓名/身份/性格/好感度/关系阶段/当前需求/情感倾向 |
| `activeEvents` | 世界规则引擎→EventDeck | 影响当前区域的事件列表（全局事件传播结果 + 遭遇事件候选） |
| `npcDepthContext` | NPC行为系统+MemOS | 若行动涉及特定NPC，提供该NPC的完整上下文（记忆摘要、互动历史） |

此结构在 V2.9 集成阶段实现，由 `GameRepository.processMainline()` 组装后注入裁决Agent的 user message。

### 6.2 叙事Agent

**调用时机**：仅在正常速度和减速模式下调用。加速模式下不调用。

**输入**：ActionResult + 模拟层上下文 + 生存状态

**输出**：沉浸式第一人称叙事 + suggestions（结构化行动选项）

**减速模式差异**：叙事密度增加，更多感官细节。suggestions时间跨度为秒级/分钟级。

### 6.3 世界叙事Agent

> 详细设计见《V3.0 Agent 配置规范 V1.0》§4（双模架构）和《世界叙事Agent详细设计文档 V1.0》（待编写）。

**架构**：双模设计——客户端模板引擎（加速期间实时状态栏）+ 云端 AI（加速结束时最终叙事总结）。详见 §3.3 加速模式步骤5。

**本地阶段**（加速期间）：
- 引擎：客户端预设模板（纯 Java/Kotlin 字符串格式化，<1ms 延迟，零成本）
- 输入：世界规则引擎提供的”预期变化”结构化数据
- 输出：格式化状态栏文本，按 2-5 秒间隔刷新 UI
- > 未来扩展（V3.1+）：若 MemOS `memos-extractor-0.6b` 提供结构化数据→文本的专门接口，可替代本地模板引擎，提升本地文本的自然度

**云端阶段**（加速结束时）：
- 调用时机：玩家发出”恢复正常速度”元行动后，批量追赶结算完成后，调用一次
- 模型：DeepSeek V4 Pro（reasoningEffort=medium, maxTokens=4096）
- 输入：整个加速期间的本地摘要序列 + 批量追赶的实际结算结果 + 自动导航报告 + 当前场景状态
- 输出：最终摘要 JSON（`final: true`），包含完整的加速总结叙事（≤300字）

**职责**：让玩家在时间快速流逝时感知世界的变化。本地阶段提供实时状态感知，云端阶段提供高质量叙事总结。

**与叙事Agent的交接**：
加速模式退出时，世界叙事Agent 的云端阶段输出包含当前场景完整状态的最终摘要。叙事Agent 接收此摘要作为初始上下文，生成进入正常模式的第一个叙事段落和新的行动选项。


## 七、角色死亡与继承

### 7.1 死亡判定

以下任一条件触发角色死亡：
- HP降至0且无救治可能
- 加速期间自动导航无法满足生存需求（无食物/水/逃跑路径）
- 特定剧情事件导致死亡

### 7.2 死亡后处理

角色死亡后：
1. 系统生成”角色最后时刻”叙事：
   - 若死亡发生在加速模式 → 由世界叙事Agent生成（选项A：死亡报告——角色如何一步步走向死亡）
   - 若死亡发生在正常/减速模式 → 由叙事Agent以特殊模式生成（输入包含死亡原因和角色最终状态）
2. 玩家可选择：
    - **读档**：回到最近的存档点
    - **观察世界**：以观察者视角继续观看世界运转（可选，选项B：遗产叙事——世界因角色生前的行动而产生的连锁反应）。观察者模式下：裁决Agent和叙事Agent暂停调用（无玩家角色可判定/叙事）；世界规则引擎和NPC系统继续每日结算；仅世界叙事Agent继续定期生成世界播报（不依赖玩家角色，以全域观察者视角描述世界演变）
    - **继承（未来扩展）**：创建新角色，继承被前任行动塑造的世界状态。新角色踏入的是同一个世界——前任的盟友可能还记得他，前任摧毁的势力不复存在，前任引发的连锁反应仍在继续

### 7.3 继承模式（未来扩展）

继承模式下：
- 新角色从预设初始状态开始（HP满、基础物资）
- 世界状态完全保留（势力分布、NPC关系网、区域状态、全局事件）
- 新角色可能通过NPC对话或环境线索了解到前任的事迹
- 同一个世界可以经历多代角色的故事

## 十、设计原则总结

1. **模拟与叙事分离**：模拟层回答“世界上发生了什么”（事实），叙事层回答“玩家如何体验它”（表达）
2. **确定性优先**：能用规则算的用规则（势力消长、NPC时间表），规则算不了的用轻量AI（阈值触发的质变评估）
3. **时间膨胀保护**：玩家思考时世界等待，玩家行动时世界响应，玩家加速时世界快进
4. **信息以玩家为中心**：模拟层计算全局，但只有抵达玩家所在区域的信息会被叙事层使用
5. **配置驱动**：区域、势力、NPC模板、事件均为可配置数据
6. **渐进式实现**：每个子版本独立可运行，逐步加入模拟层组件


## 十一、风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 时间膨胀模型玩家不适应 | 中 | 用户流失 | 三速切换有明确UI引导；初期默认正常速度 |
| 加速期间摘要流质量差 | 中 | 玩家无法感知世界变化 | 世界叙事Agent优先报告变化；摘要流定期刷新 |
| 模拟层计算量过大 | 低 | 每日结算耗时 | 初期限制势力/区域数量；优化算法 |
| AI评估结果不合理 | 中 | 模拟数据被污染 | 严格校验AI输出的数值合法性；Phase 1限制AI只能生成事件描述 |
| 剧情节点与模拟层冲突 | 中 | 主线体验受损 | 剧情管理器优先级高于模拟层；关键节点期间暂停相关模拟 |

## 一、结论摘要

**一句话：V3.0 的计算内核基本可信，但集成层大量"声明了、没接线"，主交互链路存在必现故障，且当前版本测试是红的。**

| 维度 | 结论 |
|---|---|
| 构建 | ✅ 主代码编译通过（JDK 20 / AGP 8.13.2 / Kotlin 2.0.21 / compileSdk 36） |
| 单元测试 | ❌ **当前 HEAD 无法编译**，198 个测试一个都跑不了；临时修复 1 行后实跑：**198 个跑完、1 个失败**（`android.util.Log` 未 mock） |
| 正确性 | ❌ 加速退出必现卡死、加速不推进时钟、V3 世界状态只写不读、LLM 输出零校验可崩溃 |
| 安全 | ❌ API Key 被 HEADERS 级日志完整打印（Release 也生效）；`fallbackToDestructiveMigration` 随时清档 |
| 架构 | ⚠️ 分层名义存在、边界未执行：三个上帝类（1200/1050/911 行）、domain 反向依赖 data、关键链路不可测 |
| 过度设计 | ⚠️ 约 **300 行**可立即删除、**4 个**可删依赖；另有约 **400 行**属「未接线/待决策」，不可按死代码处理 |
| 文档 | ⚠️ README 停留在 V2.2 且有 5 处硬性虚标；`doc/v3/check` 的"7/7 ✅"结论不成立 |
| 工程化 | ❌ 无 CI、无 lint/detekt、release 不混淆、无显式 DB 迁移、`.idea`/二进制垃圾已入库 |

**判断：当前是"可演示原型"，不是"可发布版本"。P0 未修完不建议对外分发 release 包。**

发现（未修，需单独排期）：
1. 自由文本被 `BranchClassifier` 归为「支线-其他」，跳过裁决 Agent——设计如此，但 adb 无法输中文，导致真机上没能触发"裁决 + 工具"主线；该组合已由 curl 冒烟覆盖。
2. **支线响应质量缺陷**：`finalGameResponse` 的 header 为 `未知/未知/未知`，story 仅 261 字且截断在半句（"把它划进"），suggestions 为空；开局主线故事 1042 字完整。问题在支线路径（prompt/令牌/流截断），需要单独用 systematic-debugging 定位。

**支线截断根因与修复（2026-10-18，`ab7dc22`）**：根因不在模型或 prompt——用应用实际 prompt + 相同参数复现，curl 原始流是合法 JSON（header 正确、story 510 字、suggestions 4 条）；真机加诊断后健康流为 `chunks=2223, sawDone=true, lastFinish=stop`。出问题的那次是**流在 `[DONE]` 之前断开**（`sawDone=false`），客户端把半截内容送进 `buildSalvagedGameResponse`，于是 header 变成 `未知`、story 截断、suggestions 清空，看起来像正常响应。

修复：拆出 `streamOnce`；流未正常结束且**没有收到任何内容**时自动重试一次；已收到半截内容或重试仍断流时发 `StorytellerEvent.Error("叙事流中断，请重试")`，不再 salvage 伪装成正常响应。测试 231 → 234（3 个新用例，修复前全红）。

> 已在 `22c0b6b` 修复同一处 P2：支线 system prompt 的"200-500 字"与共享 `JSON_CONSTRAINT` 的"≥1000字"冲突。支线现在用 `branchConstraint` 把自己的字数替换进 story 字段，主线仍保留 ≥1000 字；测试 234 → 235。

## 四、P1 问题（正确性 / 安全 / 数据）

### 网络与 LLM 交互
1. **LLM JSON 零校验 → NPE 崩溃**：`StorytellerApiClient.kt:91-97` 直接 `gson.fromJson`，Gson 绕过 Kotlin 构造器与默认值，缺 `story/suggestions/statusUpdate` 时非空字段实际为 null；`GameViewModel.kt:310-314` 的 `saveHistory(story = …)` 与 `GameScreen.kt:745` 的 `ap.riskLevel` 会崩主线程。修复：反序列化后统一校验/补默认值，禁止 null 进入 UI 与落账。
2. **网络失败被当成"行动失败"落账**：`ReasonerApiClient.kt:65-68,151-167` 捕获一切异常返回 `result="失败"`；而预裁决已先扣时间/SP（`GameRepository.kt:189-192`）且不可回滚 → 玩家白扣资源、拿到"失败"叙事，DB 与内存漂移。修复：网络/协议错误以 `Error` 中止并交上层重试，不映射为游戏内失败。
3. **`CancellationException` 被吞 + 阻塞 `readLine`**：`StorytellerApiClient.kt:65-99`、`ReasonerApiClient.kt:65-68`、`MemOSAdapter` 的 `runCatching`；取消后旧流继续读到 `[DONE]` 或 120s 超时，持续计费。修复：先 `catch (e: CancellationException) { throw e }`；改用可取消的 SSE 读取。
4. **空 API Key 无校验**：`build.gradle.kts:28-29` 默认空串，全仓无 `isBlank()` 启动检查；未配置 `local.properties` 时全部 401 静默降级为"行动失败"，排障成本极高。修复：启动校验 + 配置引导页；401 单独上报。
5. **时间推进量未钳制**：`estimatedTimeMinutes` 来自 LLM（`ActionParsed`），负数触发 `require` 异常、极大值跳天并跳过按天事件（`SurvivalStateMachine.kt:89-98`、`GameClock.kt:47-50`）。修复：入口 `coerceIn(0, 480)`。

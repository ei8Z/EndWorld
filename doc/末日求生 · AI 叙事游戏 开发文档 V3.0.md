# 末日求生 · AI叙事游戏 开发文档 V3.0

> **版本**：V3.0 动态世界模拟
> **基于**：V2.2 双Agent架构 + V2.3 物品精确计量
> **核心升级**：从“静态叙事引擎”升级为“动态世界模拟器”
> **设计哲学**：模拟层（确定性规则）与叙事层（AI创意）分离


## 一、V2的成就与局限

### 1.1 V2解决了什么

V2构建了一个可靠的“请求-响应”叙事管道：

```
玩家行动 → 裁决Agent判定 → 叙事Agent生成 → 等待下一个行动
```

这个管道在单次交互层面表现优秀：裁决有规则、叙事有质量、状态有权威。

### 1.2 V2无法解决什么

管道的隐含假设是：**世界在玩家不行动时是静止的。**

这导致了三个体验问题：

| 问题 | 表现 | 根因 |
|------|------|------|
| **时间感坍缩** | 10轮对话没过一个上午 | 时间推进完全依赖AI的suggestions |
| **世界扁平化** | 所有NPC和地点都在“等玩家” | 没有自主运行的模拟层 |
| **缺乏意外发现** | 玩家总能预测下一步会遇到什么 | 事件只由裁决Agent在行动时触发 |

### 1.3 V3的核心突破

V3引入一个**独立于玩家行动、持续运行的动态世界模拟层**。这个模拟层不是AI Agent，而是确定性的规则引擎。它确保：

- **即使玩家什么都不做，世界也在变化**
- **NPC有自己的生活和需求，不总是等着玩家**
- **远处的势力消长最终会以可感知的方式抵达玩家**

### 2.2 核心设计原则

**模拟与叙事分离**：
- 模拟层回答“世界上发生了什么”（事实）
- 叙事层回答“玩家如何体验它”（表达）
- 模拟层不调用AI，叙事层不修改事实

**玩家中心的信息锥**：
- 世界规则引擎模拟全局，但只有影响玩家所在区域的信息会被“推送”给叙事层
- 远处的事件以两种方式抵达：延迟传播（如难民潮几天后到达）和间接感知（如收音机广播、路人传言）

**确定性优先，AI增强**：
- 能用规则算的就用规则算（势力消长、资源消耗、NPC时间表）
- 规则算不了的用AI（NPC的独特对话风格、对玩家的情感反应）
- AI不是模拟器，AI是“翻译器”——把规则计算的结果翻译为有温度的叙事


## 三、模拟层核心设计

### 3.1 世界规则引擎

**职责**：管理全球范围内的宏观状态变化。这是一个纯客户端规则引擎，不调用AI。

**核心思想**：世界被划分为若干个“区域”。每个区域维护资源指数、威胁指数、势力控制度。区域之间的状态变化通过简单的数值模型计算，按游戏日结算。

**区域定义**：世界被预先划分为若干区域（如“城西住宅区”、“工业区”、“河对岸”），每个区域有：
- 资源指数（食物、水、医疗、弹药的可获取性）
- 威胁指数（丧尸密度、辐射强度、匪患程度）
- 控制势力（哪个势力在此区域占主导）
- 连接区域（相邻区域列表，决定了事件传播路径）

**势力定义**：每个势力有：
- 人口、武装程度、食物储备
- 控制的区域列表
- 与其他势力的关系（中立/同盟/敌对）
- 势力目标（扩张、防守、撤离）

**每日结算**：每经过1个游戏日，世界规则引擎运行一次：
- 各势力消耗资源（人口×消耗率）
- 各区域资源自然恢复或枯竭
- 势力间冲突判定（敌对势力在相邻区域则概率冲突）
- 末日等级影响全局（所有区域威胁指数逐步上升）
- 事件传播：上一日触发的事件沿连接区域扩散

**输出**：结算后，引擎产出一个变更列表——哪些区域的状态发生了变化。这些变更被存储，供NPC行为系统和叙事层使用。

**设计要点**：
- 不是“模拟每一个个体”，而是“模拟关键指标”
- 参考《文明》系列的区域管理，而非《矮人要塞》的实体模拟
- 引擎不生成叙事文本，只生成结构化数据
- 配置驱动：区域划分、势力初始状态、消耗公式均为可配置参数

### 3.2 NPC自主行为系统

**职责**：管理玩家已接触过的NPC的自主行为。轻量规则为主，关键NPC可选择性使用轻量AI调用增强对话深度。

**核心思想**：每个重要NPC维护三个维度的数据——时间表、需求、记忆。当玩家不在场时，NPC按时间表自主行动，其状态随世界规则引擎的结算而更新。当玩家再次遇到NPC时，NPC的当前状态和态度变化已由系统计算完成。

**时间表**：每个NPC有一个简单的日常节奏（如“早晨巡逻、下午休息、晚上值守”），决定NPC在一天中不同时段的大致位置和活动。

**需求驱动**：每个NPC有一个当前最紧迫的需求（安全感、食物、医疗、信息、复仇），需求影响其行为倾向和对玩家的态度。

**记忆系统**：NPC记住与玩家的交互历史、好感度变化、玩家是否兑现承诺。这些记忆影响未来交互。

**NPC间互动**：同一区域的NPC之间可能发生简单互动（交易、冲突、合作），结果由概率和关系网决定。

**触发时机**：NPC状态按游戏小时更新。更新不调用AI——只有数值变化和状态标签变更。

**设计要点**：
- 不是每个NPC都有完整AI大脑，大部分NPC是“状态卡片”
- 重点NPC（与玩家有多次交互的）数据更深，次要NPC数据更浅
- 参考RDR2的NPC记忆系统，而非Inworld AI的去中心化多Agent
- NPC的“活着”感来自状态的一致性和记忆的持久性，而非复杂的自主推理


## 四、叙事层调整

### 4.1 新增：世界叙事Agent

**职责**：当玩家选择时间跨度较大的行动（block或chapter级别）时，生成时间流逝摘要。当世界规则引擎的重大变化抵达玩家所在区域时，生成世界事件广播。

**与叙事Agent的区别**：
- 叙事Agent处理“逐轮交互”——每一轮玩家行动对应一段叙事
- 世界叙事Agent处理“时间跳跃”——一段时间的流逝被压缩为一段摘要
- 两者使用相同的API，但系统提示词不同（世界叙事Agent强调时间感和宏观描述）

**调用时机**：
- 玩家选择block/chapter级别的行动时
- 世界规则引擎的重大事件抵达玩家区域时（如“难民潮涌入”）
- 章节过渡时

**输入**：时间跨度 + 期间发生的状态变更（由模拟层提供）+ 玩家所在区域的新状态

**输出**：300-800字的时间流逝摘要叙事

### 4.2 调整：叙事Agent的suggestions生成

叙事Agent不再独自承担suggestions的生成。改为：

**客户端预生成suggestions结构**：
- 客户端根据当前场景、世界规则引擎的区域状态、NPC行为系统的NPC状态，按四级结构（即时行动/中期任务/跨越行动/支线任务）预生成suggestions框架
- 每个框架包含：actionParsed的大部分字段（由客户端从模拟层数据中提取）

**叙事Agent负责suggestions的自然语言润色**：
- 叙事Agent接收预生成的suggestions框架
- 为每个选项生成自然的label、riskHint、timeHint
- 确保叙事风格与当前故事一致

**职责分离的好处**：
- suggestions的结构正确性由客户端保证（不依赖AI）
- suggestions的文学质量由叙事Agent保证
- 两者各司其职，减少幻觉空间

### 4.3 保留：裁决Agent

职责基本不变，但输入更加精确：
- 接收世界规则引擎产出的当前区域状态（结构化数据，非需要理解的文本）
- 接收NPC行为系统产出的当前NPC状态（结构化数据）
- 基于这些精确输入进行裁决

裁决Agent不再需要“理解世界”——它只需要“在给定的精确条件下判定行动结果”。


## 五、数据流：一个完整的游戏日

```
游戏日结束（客户端检测）
        │
        ▼
┌───────────────────────────────────────────────┐
│  世界规则引擎 每日结算                          │
│  - 计算各区域资源变化                           │
│  - 判定势力间冲突                               │
│  - 传播上一日事件                               │
│  - 产出：RegionStateUpdate[]                   │
└───────────────────────────────────────────────┘
        │
        │  提取影响玩家当前区域和相邻区域的变更
        ▼
┌───────────────────────────────────────────────┐
│  NPC行为系统 按小时更新                         │
│  - 基于新的区域状态更新NPC位置/状态              │
│  - 处理NPC间互动                                │
│  - 产出：NpcStateUpdate[]                      │
└───────────────────────────────────────────────┘
        │
        │  若玩家选择block/chapter行动
        ▼
┌───────────────────────────────────────────────┐
│  世界叙事Agent                                 │
│  - 输入：时间跨度 + 期间状态变更                │
│  - 输出：时间流逝摘要叙事                       │
└───────────────────────────────────────────────┘
        │
        │  若玩家选择instant/scene行动（正常轮次）
        ▼
┌───────────────────────────────────────────────┐
│  裁决Agent → 叙事Agent                         │
│  (流程不变，但输入包含模拟层提供的精确状态)      │
└───────────────────────────────────────────────┘
```

**玩家感知**：无论世界规则引擎在后台计算了多少，玩家只感受到三件事：
1. 正常行动时，叙事质量更高（因为裁决Agent有更精确的输入）
2. 时间跳跃时，世界叙事Agent提供优美的过渡摘要
3. 偶尔会通过广播、传言等方式听到远处的消息

## 八、设计原则总结

1. **模拟层不调用AI**：世界规则引擎和NPC行为系统是确定性规则引擎。它们的输出是结构化数据，不包含叙事文本。

2. **叙事层不修改事实**：裁决Agent、叙事Agent、世界叙事Agent接收模拟层的事实数据，将其转化为文学叙事，但不得修改数据。

3. **信息以玩家为中心**：模拟层计算全局，但只有抵达玩家所在区域的信息会被叙事层使用。远处的事件要么延迟传播，要么以间接方式被感知。

4. **配置驱动**：区域划分、势力初始状态、NPC性格模板、世界事件均为可配置数据，支持不同末日类型的预设。

5. **渐进式实现**：V2.4先验证suggestions结构，V2.5-V2.7逐步加入模拟层组件，V2.8集成，V3.0正式发布。每个子版本独立可运行。


## 九、风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 世界规则引擎计算过于复杂 | 中 | 每日结算耗时过长 | 初期限制区域数量（10-15个），后续优化算法 |
| NPC行为系统数据量膨胀 | 中 | 内存/存储压力 | 仅追踪玩家已接触的NPC（约20-50个），未接触的NPC状态由世界规则引擎宏观描述 |
| 世界叙事Agent与叙事Agent风格不一致 | 低 | 玩家感知割裂 | 共享部分系统提示词（如五感描写规则），统一风格基准 |
| 模拟层数据与AI叙事脱节 | 中 | AI未充分使用模拟层数据 | 在裁决Agent和叙事Agent的User Message中强制要求引用模拟层数据 |
